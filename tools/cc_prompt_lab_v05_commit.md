## 1. Продукт #1 — одной фразой

Операционная система для **создания и сопровождения ПО силами ИИ-агентов**: спецификация-как-контракт
+ координационная подложка + дисциплина верификации + петля самообучения. На выходе — продукт
**качественный, самодокументируемый, сопровождаемый агентами, масштабируемый и эволюционирующий**.

Не «ИИ пишет код» — это лишь компонент. Суть — **способ организовать разработку так, чтобы её носителем

## 1a. Что координируем: распределённую человек+AI команду (новое в v0.5)

Заземление: E-019, E-020 (оба ЗАРАБОТАНО, продукт-определяющие).

Раннее приближение «N агентов под одним оператором» **опровергнуто живьём**: реальная конфигурация —
**два независимых человек+AI-узла в разных городах** (Cowork-A = Max; Cowork-B = партнёр), связанных
**только git-кросс-каналом** (`coord`). Это ровно наш two-Cowork-слой (§44 операционного ТЗ).

**Принцип:** Метод координирует не агентов под одним человеком, а **распределённую команду людей-с-агентами**.
Координационная подложка (git + протокол §42/cross) обслуживает **людей И агентов единообразно**:
- git даёт async-развязку в **пространстве** (разные города) и **времени** (каждый включается, когда может);
- «два координатора» = genuine человеческий параллелизм (два человека, два места), не размноженный оператор;
- остаточная стоимость связи = **триггер** (no-poll: узел читает по поку), не контент — контент уже git-backed (E-019).

**Почему это СИЛЬНО продаёт #1:** онбординг чужой команды = ровно установка этой подложки. То, что мы
строим для себя, и есть отчуждаемый продукт (§9). Надёжная доставка между узлами критична вдвойне — это
связь между **людьми**, не только процессами.

## 3. Центральная ставка (самое смелое и самое ценное)

**Компрессия роли оператора.** Apparatus экстернализует архитектурное суждение системы в
**структурированный опросник** (планирование / реализация / поддержка) настолько полный, что вести
систему может **квалифицированный инженер БЕЗ авторства этой системы** — отвечая на опросник на качестве,
которое дал бы автор.

**FROM → TO (приколочено, не лозунг):**
- **FROM:** автор-архитектор — спланировал систему, держит экспертизу и мнение по изменениям (сегодня: оператор на RTM).
- **TO:** оператор **без авторства этой системы**, который **квалифицированно отвечает на опросник** в планировании / реализации / поддержке.

Сжимаем **системно-специфичное тацитное знание (авторство)**, НЕ инженерную квалификацию. Удар по
**bus-factor / стоимости онбординга / привязке-к-автору** — то, за что платит команда (#1).

**Асимптота (горизонт, не выброшено).** «Сопровождаемое не людьми» = предел оси (§0) при квалификации → 0.
Moonshot, к которому идём; сейчас в base-hit точке: автор → не-автор. Старая ставка опровергнута нашим же
**E-001** (оператор на критическом пути) — снята как *текущая*, сохранена как *горизонт*.

**(v0.5) Одна ось, измеримая в ops-домене.** Deploy-эпизоды **E-010** (self-describing deploy-state) и
**E-017** («verified GREEN» ≠ воспроизводимо автоматизировано) — НЕ вторая «центральная ставка», а **тот же
вектор компрессии, инстанцированный в деплое**: «manual-touch-points/деплой → 0» ЕСТЬ «ходов оператора /
единицу прогресса → 0» (метрика E-001). Эффект для ставки: воспроизводимость **измерима уже сейчас**, поэтому
часть «сопровождается агентами» переезжает с чистого горизонта **в измеримое настоящее**. Зрелость деплоя =
manual-touch-points → 0 (E-017); сервер сам сообщает своё состояние, иначе апгрейд = агенто-археология (E-010).

**Главный риск — инверсия компрессии.** Опросник покрывает только **известное** пространство вопросов.
Глубинная ценность автора — знать, какой вопрос НЕ задан: непредусмотренное взаимодействие, ненаписанный
инвариант. Если «квалифицированно ответить» начнёт требовать понимания режимов отказа аппарата + неявных
инвариантов — **планка не падает, а растёт.** Лаборатория обязана это ловить.

**Два следствия в дизайн (заземлены на harvest):**
- **Валидация ОТВЕТОВ, не только записей.** Не-автор может уверенно ответить неверно (нет модели системы).
  Нужен слой проверки: согласуется ли ответ с инвариантами / историей. Это **E-002 («tool-success ≠ delivery»),
  перенесённый на суждение**; и **E-009** (нарратив действия ≠ выполнение) — на самоотчёт самого оператора.
- **Опросник = функция durable-truth + семантики.** Чтобы вопросы были правильными, аппарат должен читать
  **смысл** системы, не байты — что смыкает ставку с гипотезой семантической легибельности (§6a). **Две
  открытые дыры — одна проблема:** холодный агент восстанавливает *замысел* ≡ опросник захватывает модель автора.

**Статус: ГИПОТЕЗА.** Заработано (E-001): оператор — серийная функция, опросник-до-GO — наша практика.
Заработано измеримо (E-010/E-017): touch-points → 0 как ops-инстанс компрессии. НЕ заработано: что опросник
захватывает достаточно тацитной модели автора, чтобы не-автор отвечал на качестве автора. Это ядро ставки, оно недоказано.

**Тест, который заработает или убьёт ставку:** взять кусок RTM, спланированный автором → сгенерировать
опросник → провести изменение руками квалифицированного **не-автора** через опросник → сравнить исход с
авторским решением. Разрыв = неизмеренный тацитный остаток. **NB: автор — негодный судья этого теста**
(видит легибельную часть суждения, слеп к тацитной). Судить по **исходу**, не по «автор считает, что опросник покрыл».
(DESIGNED-эксперимент — `E-022-operator-compression-test.md` + `RUN-PLAN-AgentGrid-informedGO.md`.)

## 4. Пять столпов (и что каждый требует от системы)

| Столп | Что требует | Заземление |
|---|---|---|
| **Качество** | верифицируется, не декларируется — *tool-success ≠ delivery* | **E-002 ✓ ЗАРАБОТАНО** (+ E-009 на самоотчёт) |
| **Самодокументируемость** | спека = живой контракт **под дисциплиной doc↔code-верификации** (НЕ «синхронна по умолчанию») | **E-014 ⚠ РЕФАЙН: спека может врать** — §24 IIS vs Kestrel-реальность |
| **Сопровождаемость агентами** | легибельность для ИИ: явные правила, инварианты, восстановимое состояние; самоописываемое deploy-состояние | **E-003 ✓ байтовый уровень; E-010 ✓ self-describing state; семантический — гипотеза** |
| **Масштабируемость** | параллельные роли, тонкие швы, координационная подложка; распределённая человек+AI команда | **E-004 ✓ + E-019/E-020 ✓ (распределённость)** |
| **Эволюция / обучение** | петля: инцидент → урок → **правило подложки**; петля не лучше своей поверхности захвата | **E-006 ✓ (no-loss capture); сам Evidence-Log = инстанс петли** |

**(v0.5) Понижение тона столпа-2 — сознательно.** E-014: даже «единый источник правды» (§24) **соврал**
(объявил IIS-хостинг, реальность = Kestrel-сервисы). Стейл-спека тихо протаскивает ложные допущения в
производные артефакты. Это **E-002, применённый к СПЕКЕ**: «спека объявила X ≠ X истинно». Поэтому статус
столпа — не «есть синхронность», а **«живой контракт + дисциплина doc↔code + известный режим отказа»**.
Честность тут усиливает флагман: мы продаём спеку-контракт, зная и показывая, где она ломается.

Пятый столп — самый недооценённый: **процесс, улучшающий собственные правила из собственных аварий.**
Зерно «чуда» — не «ИИ пишет код», а **самодокументирующийся, самообучающийся многоагентный конвейер.**
*(NB: Evidence-Log сам по себе — живая демонстрация пятого столпа; E-006 доказал, что петля не лучше своей
поверхности захвата — маршрутизируй эпизод немедленно в долговечное хранилище, а не в эфемерный чат.)*

## 5. Конвейер: идея → ??? → продукт

«???» — не один чёрный ящик, а фазы, прожитые на RTM:

1. **идея → единый источник правды** (спека-контракт, живой, не архивный) — *но спека верифицируется против реализации, E-014*;
2. **спека → декомпозиция** на параллелящиеся роли с тонкими швами (специализация);
3. **параллельное исполнение** поверх координационной подложки (git-как-истина, claim/lock/барьер, CC-дисциплина) — *заземлено E-003 (git-как-истина), E-004 (single-owner/lock), E-019/E-020 (распределённые узлы через git)*;
4. **исполнение → верификация** (tool-success ≠ delivery; доказательство, а не отчёт) — *заземлено E-002, E-009*;
5. **верификация → релиз/деплой** (воспроизводимая машинерия, ops-слой) — **самая заземлённая фаза (v0.5):**
   - deploy-намерение first-class, гейт деструктива (fresh-install vs in-place) — **E-007**;
   - канонический артефакт однозначен: version-stamp, уникальная распаковка, чистка staging — **E-011**;
   - read-actual-state: auto-detect фактической версии сервера, не доверять спеке — **E-012**;
   - «где прод» = connection string живого сервиса, не порт по умолчанию — **E-013**;
   - отличать диагностический stderr-шум от ошибки; rollback-on-abort, не только на exit-code — **E-015**;
   - «blocking?» проверять по ВСЕМ путям (fresh / re-apply / rollback) — **E-016**;
   - stop-service ≠ kill-process: wait-for-exit + force-kill orphan — **E-018**;
   - зрелость = manual-touch-points → 0, push-button воспроизводимость, не эксперт-babysitting — **E-017**;
6. **петля** — каждый инцидент → урок → правило подложки — *инстанцируется Evidence-Log (E-006)*.

Задача трека — превратить это из «как мы интуитивно делаем» в **отчуждаемый, повторяемый продукт.**

## 6. Роль RTM View — лаборатория, не самоцель

**Каждый принцип метода обязан быть ЗАРАБОТАН конкретным эпизодом в RTM View.** Нет эпизода — нет
принципа. RTM — **генератор доказательств**. Редкое сырьё: проект, документирующий собственные провалы
по горячему (PD-005/006/007, L-SC-01..20, SF-NNN, seam-конфликт §44). Метод, замешанный в грязи, а не в
презентации. **GO подтвердил: RTM — валидная лаборатория именно для #1.**

## 6a. Что harvest ДОКАЗАЛ для #1

Источник: `Evidence-Log.md`, E-001..E-021 (канон).

**Сквозной вывод:** рабочая поверхность (mount/file-bus) **враждебна и лоссова**. Надёжность метода
переносится с неё на **триаду process-guarantee**:

- **Верификация артефакта** (E-002, + E-009 на самоотчёт): статус инструмента / нарратив агента ≠ доставка; проверяем содержимое/хеш против истины.

- **Дисциплина владения/записи** (E-004, E-021): общая поверхность → single-owner или сериализация, иначе тихий lost-update — и это касается **файлов самого Метода**.

deploy-intent first-class (E-007), однозначный артефакт (E-011), гейт «шум vs ошибка» + rollback-on-abort
(E-015), path-полный risk-triage (E-016), kill-orphan (E-018), и метрика зрелости touch-points → 0 (E-017).
Это заземляет **фазу-5** конвейера и **ops-инстанс** центральной ставки.

**Что harvest НЕ закрыл (остаётся гипотезой):**

1. **Семантическая легибельность холодного агента.** E-003 доказал восстановление **байтов** durable truth.
   Что агент восстанавливает **замысел** (intent, инварианты как смысл) — **не доказано**. Самая твёрдая
   часть центральной ставки. **Та же дыра, что компрессия оператора (§3):** «опросник захватывает модель
   автора» ≡ «агент восстанавливает замысел». Один эпизод-тест (E-022) закрывает обе.
2. **Все три дыры → #2** (§7), не закрыты и не должны были в этом harvest.

## 6b. Правило целостности — изоляция RTM↔Метод

Решение координатора A (2026-06-08). **Предохранитель доказательной базы**, без него §6/§7 ничего не стоят.

1. **RTM преследует свои цели; Метод НАБЛЮДАЕТ, не рулит.** Лаборатория не подгоняется под гипотезу.
2. **Harvest ретроспективный, не проспективный.** Принцип извлекается из *уже случившегося*. **Исключение:**
   явно-помеченные **DESIGNED-эксперименты** на **реальной RTM-нужде** (напр. E-022 на фиче Agent Grid —
   requirement-driven, не AI-фантазия).
3. **Поток односторонний:** RTM → улика → Метод. Метод не вливает требования обратно в RTM.
4. **Предохранитель — дисциплина, не механизм.**

**Зачем (и риск на виду):** если Метод начнёт рулить RTM, эпизоды станут **самоисполняющимися** — мы будем
«доказывать» гипотезу, подстроив лабораторию; улики обесценятся. Изоляция сохраняет RTM как **независимый**
генератор доказательств.

**Моё несогласие — на запись (не отменяет решение):** «предохранитель — дисциплина, не механизм» — это
**сам по себе ставка того же класса, что центральная**: опора на человеческую дисциплину там, где механизма
нет. Наш же **E-004** (два координатора тихо переписали §44), **E-021** (copy-clobber Evidence-Log) и **E-023**
(frozen-first charter) — про то, что тихие отказы случаются ровно там, где дисциплина без механизма. То есть
правило изоляции защищено тем самым типом гаранта, который лаборатория уже трижды ловила как ненадёжный.
Принимаю как осознанный долг; кандидат на лёгкий механизм-маркер (явная плашка DESIGNED + лог направления потока).
