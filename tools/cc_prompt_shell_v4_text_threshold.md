## Что делаем

### 1. Одна общая функция, в месте, видимом и виджетам, и тестам
Новый файл `src/CcDashboard.Contracts/Common/ThresholdTextMatch.cs` — статический класс с двумя чистыми функциями:
одна отвечает «совпало ли значение с образцом при данном виде сравнения» (семь видов + поведение по умолчанию),
вторая — «считается ли значение пустым» (пустая строка или одни пробелы).
**Почему именно `Contracts`** [измерено автором]: `CcDashboard.Web` ссылается на `Contracts`, и
`tests/CcDashboard.Tests.Unit` ссылается на `Contracts` — значит функция достаётся и виджетам, и тестам
**без единой новой ссылки в решении**. `Tests.Unit` на `Web` НЕ ссылается, поэтому логика, оставленная внутри
`.razor`, тестами не покрывается — это и есть причина выноса.
Вид сравнения приходит строкой как есть из настройки; неизвестное или отсутствующее значение → **equal**
(совместимость со старыми конфигами, п.5 приёмки).

### 4. Лог аномалии — по переходу, не по каждому обновлению
При приходе сырого `NaN`/`Infinity`/`-Infinity` писать **Warning** в лог Shell: идентификатор метрики, виджет,
идентификатор строки, сырое значение.
⛔ **В лог не попадают персональные данные.** Идентификатор строки — это **`RowId`** (есть в обоих:
`QueueRowData.RowId`, `AgentRowData.RowId`) плюс `GridId`. **Нельзя** писать отображаемое имя, телефон,
добавочный и любое значение из `Metrics`: имя агента лежит именно там. В `QueueGridWidget` есть отдельное
поле `QueueName` — **тоже не писать**, достаточно `RowId`; строка лога должна быть одинаковой по составу
в обоих виджетах. Логгер в обоих виджетах есть
(`[Inject] private ILogger<…> Logger`, Q :230).
⛔ **Не на каждый пуш.** Движок шлёт данные постоянно; запись — **на переход ячейки в аномалию** и одна на
**выход** из неё. Значит нужно помнить состояние «эта ячейка сейчас аномальна» между обновлениями.
Предикат: N одинаковых аномальных обновлений одной ячейки → **1** запись; возврат к норме → **1** запись;
обычные значения → **0** записей.
