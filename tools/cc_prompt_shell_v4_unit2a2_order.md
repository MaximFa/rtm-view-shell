## Дефект — тихий, и потому опасный
Подписи в `AgentGridWidget.razor` разбирают шаблон так:
```
showTpl.Split(new[] { "{0}", "{1}" }, StringSplitOptions.None)
```
Разделители применяются **оба сразу**, а значения подставляются в порядке появления частей. Пока во всех
трёх словарях порядок прямой (`{0}` раньше `{1}`) — на экране верно [пере-снято автором: en `Showing {0} of {1}`,
he `מוצגים {0} מתוך {1}`, ru `Показано {0} из {1}`].
Но переводчик вправе поставить `{1}` раньше `{0}` — в RTL это естественное желание. Тогда `Split` всё равно
вернёт **три** части, запасная ветка не сработает (длина сойдётся), и числа молча встанут не на свои места:
«показано 41 из 7» вместо «7 из 41». Ошибка не падает, не логируется и выглядит как правдоподобное число —
худший вид ошибки для экрана, на который смотрят, не перепроверяя.

шаблон и массив значений, возвращает **последовательность частей**: литеральный кусок текста либо значение
с его номером — так, чтобы вызывающий вывел литералы как текст, а значения обернул в `<bdi>`.
Номер берётся из самого плейсхолдера (`{0}`, `{1}`, …), а не из порядка появления.
