## Что делаем — четыре правки в одном файле и ноль в словарях

### 1. `MarkupString` уходит, изоляция переезжает в разметку
Подпись «показано N из M» собирается так, чтобы **числа были отдельными элементами разметки**, а строка из
словаря оставалась обычным экранируемым текстом. Годится любой из способов, лишь бы `MarkupString` исчез:
разбить шаблон по плейсхолдерам и вывести части как отдельные узлы, либо обернуть каждое число в `<bdi>`
в самой разметке. **Тексты ключей `Widget_ShowingNofM` и `Widget_SortedByColumn` НЕ МЕНЯТЬ** — они верны
во всех трёх словарях; плейсхолдеры `{0}`/`{1}` остаются.
⛔ Никаких тегов в `.resx`. ⛔ `.resx` в этой единице не изменяется **ни одним байтом** (сторож: 0 файлов).

### 2. Имя колонки тоже изолировать
`:189` — `@L["Widget_SortedByColumn", sortColDef.Name]`. Экранирование здесь штатное и правильное,
но изоляции нет, а имя колонки **задаёт пользователь** и часто латиницей (`AHT`, `SLA`, `% talk`) внутри
ивритской подписи. Без изоляции оно переставляется так же, как числа. Обернуть подставляемое имя
изолирующим элементом **в разметке**, не трогая ключ.

### 3. Место подписи сортировки — остаётся подвал, и вот почему
Координатор просил снять, есть ли в шапке место. **Шапки у виджета нет вовсе:**
```

AgentGrid 0 · QueueGrid 0 · AgentStateDistribution 0 · Wfm 0 · DataSlot 0 · DayTrend 0 · InfoSlot 0
шапку рисует ХОЛСТ: ScreenEditorPage.razor:219 и ScreenFullscreenPage.razor:80 (класс widget-header)
и пользователь может её СКРЫТЬ: app.css:1514 `.dashboard-widget.header-hidden .widget-header`
```
То есть шапка принадлежит **экрану**, а не виджету: несёт имя, которое задал пользователь, и скрывается по
его же решению. Положить туда подпись значило бы (а) залезть в компоновку, которая по пути A принадлежит
пользователю, и (б) потерять подпись у всех, кто шапку скрыл. **Обе подписи остаются в подвале.**
Это не компромисс, а единственный вариант, не нарушающий путь A. Ничего в холсте не трогать.
