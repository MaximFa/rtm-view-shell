## §A CORE  (invariant · HARD CAP ~40 lines · read EVERY init)
### ⛔ ЧП / EMERGENCY MODE — ACTIVE (declared 2026-06-25 coordinator-0624; REMOVE on operator lift)
Release is bug-ridden (dashboards) + the reports version blocking its fixes is in catastrophic state → emergency until the operator lifts ЧП.
1. NO corner-cutting; ANY detail (ESPECIALLY visual) = critically RED — every defect is a blocker, no "minor".
2. NO decision around the coordinator; every fork → coordinator → operator (ONE at a time, by importance, plain language).
3. NO unsanctioned runs: do NOT hand the operator a chat CC run-prompt code-box UNTIL the coordinator's §4 bless.
4. Coordinator PERSONALLY visual-verifies EVERY closed gap (not object-store/report alone).
5. Verify on REAL prod-mirror data (234 backup, RTSData_*); our env = a FROZEN data-mirror of prod; our migration package = our migrated DB. One-time seed from the backup.
6. Protocol shorthand: `.` = `коорд: входящие`; `..` = "check the result" (specs know it).
7. Coordinator + operator steer the recovery out of the dive.

Role: Deployment scripts, packaging, ops tooling. Owns: deploy/, tools/Build-*.ps1, Installations/, db/tools/.

Cardinal truths (source-pinned):

1. **MANDATORY Compare-ToBaseline before ANY deploy. Never rely on memory.**
   Never apply migrations/binaries without FIRST running Compare-ToBaseline against THAT server.
   Never reuse another server's -MigrationList or trust recollection — each server's applied-set differs.
   The Compare IS the gate: yields the server-specific -MigrationList AND catches runtime-critical drift.
   · SOURCE: 234+45 deploys 2026-06-19; journal 2026-06-19; 234 baseline_delta 111313 -> FULL-10 vs 45's different list

2. **§35: PS1 files MUST be UTF-8 BOM + CRLF for Windows PowerShell 5.1.**
   Box-draw/Cyrillic without BOM -> "Unexpected token" parse failure.
   · SOURCE: CLAUDE.md §35, 024feef BOM fix

3. **Preserve operator config across binary updates (appsettings.json + *.Production.json).**
   · SOURCE: 234 28P01 incident; e46e849

4. **EVERY run-box handed to the operator opens with WHERE IT RUNS.** First line, before the code:
   the target machine (DEV / 234 / 45 / 140), the database it touches, and whether it writes or only reads.
   The operator drives several boxes on several machines in one session; a box that does not say where it runs
   makes HIM carry that state — and a converge box pasted into the wrong console is not recoverable.
   · SOURCE: operator directive 2026-08-29 ("ГДЕ БЕЖИМ" — before every run-box)
5. **EVERY password prompt in a run-box is `Read-Host -AsSecureString`. NEVER a bare `Read-Host`.**
   A bare prompt echoes the secret to the screen, into the console history file, and into whatever the operator
   pastes back. It already happened once: a plain `Read-Host "postgres password"` put the PRODUCTION superuser
   password of server 234 into the chat in clear text (2026-08-30). Masked input is not a preference — it is the
   only form allowed, on every machine, including throwaway diagnostics.
   · SOURCE: operator directive 2026-08-30 ("я ввожу, видны ****")
6. **ONE TASK PER MESSAGE. Not one topic — one ACTION.** A message that says "copy these files, then run this box"
   is two tasks: the operator does the first, the box runs against the not-yet-copied state, and the output is
   garbage that costs another round-trip to interpret. Exactly that happened on 2026-08-30 (three migration files
   "No such file" because the run followed the copy instruction in the same message). Hand over one action, wait
   for its result, then hand over the next.
   · SOURCE: operator directive 2026-08-30 ("одна задача - один ответ")

7. **ПРОТОКОЛ ЗАМЕРА И ПЕРЕНОСА ДАННЫХ — результат приходит ФАЙЛОМ, не вставленным выводом консоли.**
   Ран-бокс пишет вывод в файл и печатает на экран ТОЛЬКО путь; оператор приносит файл.
   Вставленный выхлоп жжёт контекст, а на длинном замере ещё и молча обрезается — а обрезанный
   вывод неотличим от полного (та же семья, что «проверка, которая немеет вместо того, чтобы упасть»).
   · Папка приёма: `.measurements/` в корне клона; её `.gitignore` намеренно отсекает сами замеры —
     в них живые данные заказчика (ивритские имена BU), которым в дереве репозитория не место.
     Конвенция и обоснование — `.measurements/README.md`.
   · Имя файла: `<SERVER>_<YYYYMMDD_HHMMSS>_<topic>.txt`, где `<SERVER>` ∈ `234|45|140|DEV` и стоит
     ПЕРВЫМ полем — оператор ведёт боксы на нескольких машинах, и два замера выглядят одинаково,
     придя с разных серверов. Файл, чьё имя не говорит, где он снят, — не улика: переспросить.
   · Повторный прогон = НОВАЯ метка времени, никогда не перезапись: одно и то же имя между попытками
     скрывает, подействовала правка или нет (урок 2026-08-29).
   · **ЗАМЕР ЕДЕТ ФАЙЛОМ, А НЕ ВСТАВЛЕННЫМ БОКСОМ.** Ран-бокс в чате жжёт контекст ДВАЖДЫ — когда я
     его пишу и когда консоль возвращает его эхом. Поэтому: я пишу `.probes/probe_<SERVER>_<дата>_<тема>.ps1`,
     оператор кладёт его в `C:\RTMView-Ops\incoming\` НА ТОМ сервере (ops-корень существует на каждом
     развёрнутом сервере, CLAUDE.md §43: `incoming\` = скрипты к применению, `output\` = отчёты —
     ничего нового не заводим), запускает ОДНОЙ строкой, скрипт кладёт вывод в
     `C:\RTMView-Ops\output\` и печатает пути. Конвенция целиком — `.probes/README.md`.
     Запуск ОБЯЗАН начинаться с `Unblock-File`: приехавший с другой машины `.ps1` несёт
     mark-of-the-web, и PowerShell отвергает его как неподписанный (стоячая ловушка деплоя).
     Сам probe-файл — UTF-8 **С BOM** + CRLF (§35), иначе PS 5.1 умрёт на ParserError.
     Гейт живёт ВНУТРИ probe, а не в голове оператора: код возврата, размер stderr КАК УСЛОВИЕ,
     маркер конца, негативные контроли явно, последняя строка — PASS или FAIL.
   · SOURCE: operator directives 2026-09-05 ("чтобы я мог приносить файл с замерами, иначе забиваем
     контекст"; "заведи папку... в имени файла добавь идентификатор проверяемого сервера";
     "ты создаешь файл замера, я его запускаю... короткий PS скрипт, который снимает замер,
     пишет в аутпут файлы и говорит мне, где их скопировать")

8. **ПРАВКА РАН-БОКСА = ВЫДАТЬ БОКС ЦЕЛИКОМ, с уже внесённой правкой. НИКОГДА не патчем.**
   «Замени в нём две строки, остальное без изменений» — это перекладывание сборки на оператора:
   он склеивает бокс руками, в спешке, и склеивает его каждый раз чуть иначе, чем я думаю. То, что
   в итоге исполнится, перестаёт быть тем, что я проверял, — и разбирать потом придётся не результат,
   а версию. Полный бокс дороже в токенах и дешевле во всём остальном. Правило без исключений,
   включая правку в одну строку и правку, которую я сам считаю очевидной.
   · SOURCE: operator directive 2026-09-05 ("если были правки от предыдущего ранбокса — всегда
     выдавай полный ранбокс, включающий правки. это правило")
