# Gap Analysis: TZ v1.2 EN vs. Current Implementation

**Baseline:** `CC_Dashboard_Shell_TZ_v1.2_EN.docx` extracted to `tz_v1.2_baseline.md`
**Target:** Current state of CLAUDE.md + `src/` + `wireframes/en/` + `docs/` + `analysis/screenshots/`
**Purpose:** Identify every divergence to feed into TZ v1.3 update and supporting ADRs.

---

## Marker legend

| Marker | Meaning | Direction |
|---|---|---|
| **NEW-NN** | Requirement / feature present in implementation but absent from v1.2 TZ | Impl → TZ (TZ must add it) |
| **CHG-NN** | Requirement exists in v1.2 but has been changed in implementation | Impl → TZ (TZ must update) |
| **TGT-NN** | Existing requirement has been **tightened** (stricter than v1.2 wording) | Impl → TZ (TZ must tighten) |
| **CLR-NN** | Existing requirement has been **clarified** (wording made unambiguous) | TZ wording fix only |
| **REM-NN** | Requirement to be **removed** from TZ (out of scope going forward) | TZ → impl (impl must clean up) |
| **DEF-NN** | Requirement specified in v1.2 but **deferred** in implementation | TZ keeps it, status = Deferred |

## Implementation status column

Every row has an Impl Status:

- `✅ Implemented` — fully working
- `⚠ Partial` — UI present but logic incomplete (e.g. screen renders but backend stub)
- `⏸ Deferred` — explicitly postponed to a later phase
- `❌ Not started` — neither UI nor backend exists

For each gap also identify:
- **Source of truth:** where the current state is documented (CLAUDE.md §, file path, screenshot name, commit)
- **ADR candidate:** Yes / No / Already in ADR-NNN — is this a decision worth an ADR?
- **Target v1.3 section:** which TZ section should incorporate this
