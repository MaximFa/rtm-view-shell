**Max (уточнил продукт):** «ты — человек, имеющий идею, но не имеющий образования и квалификации для её
реализации. Мы предоставляем его личного исполнителя, говорящего на его языке (не лингвистически,
ментально), опрашивающего, задающего вопросы, пока не будет получен GO на реализацию. потом —
формализация — создание ТЗ, разбивание на роли, создание исполняющих ролей, координатор, спринты,
проверки, бета версия… Для пользователя: проверь и скажи, если что не так.»

**Координатор-A (суть):** Форма правильная, сильнейший инстинкт — «опрашивать до GO» (большинство
«ИИ соберёт приложение» проваливаются на недоспецифицированной идее). Что не так / недоговорено:
(1) **Верификация доказывает соответствие СПЕКЕ, не пригодность ПОТРЕБНОСТИ** — самая глубокая дыра;
пользователь без квалификации не знает, чего не знает, его GO может быть уверенно-ошибочным; опрос
нужен с дисциплиной информированного GO. (2) Весь apparatus предполагает квалифицированного оператора
(тебя) — для профана роль оператора надо свернуть. (3) Конвейер односторонний, GO один — нужны staged-GO
+ обратная петля валидации на языке пользователя. (4) Свести две ценности в цепочку: кто не может
построить — не может и сопровождать → система обязана сопровождать сама. (5) Граница ответственности:
профан не может оценить результат. Вердикт: костяк здоровый; три дыры — (1) спека-верна ≠ нужное,
(2) роль оператора не свёрнута, (3) нет петли валидации на языке пользователя.

**Координатор-A (суть):** Параллель не пустая: «Метод» — про дисциплину смотреть на неудобную правду,

**односторонний ретроспективный harvest** (записываем, что случилось, не инженерим ради урока). Честная
оговорка: изоляция не герметична — один координатор и один оператор мостят оба трека; реальный
предохранитель — дисциплина, изоляция лишь делает её легче держать.

**Координатор-A (суть):** «Заверну изоляцию в charter» = превратить разговорный принцип в записанное
правило методологии (новый пункт «Целостность лаборатории» рядом с §6/§7): (1) RTM преследует свои
цели, Метод наблюдает не рулит; (2) harvest ретроспективный, не проспективный — КРОМЕ явно-помеченных
DESIGNED-экспериментов на реальной RTM-работе; (3) поток односторонний, предохранитель — дисциплина.

## 9. Протокол informed-GO (предложен Lab)

**Max (relay из Lab):** Протокол: автор пред-регистрирует решение + трогаемые инварианты (запечатано) →
аппарат генерит опросник без автора → не-автор ведёт изменение только по опроснику + git/спеке → судим
по исходу, не по совпадению рассуждений. Две поверхности отказа: неполнота опросника (не спросил) vs
ошибка ответа. Приоритетный киллер ставки — тихое нарушение незаписанного инварианта = «незаданный
вопрос». Две развилки: (1) кто играет не-автора — холодный агент vs реальный человек; (2) субъект —
какой кусок RTM с известным незаписанным инвариантом.

**Координатор-A (суть):** Протокол сильный — это пре-регистрация + слепая репликация (анти-bias из
науки). Острое — разделение двух поверхностей отказа (чинятся разными руками: аппаратом vs знанием
домена). Связь с изоляцией: протокол запускается НА RTM = Метод→RTM (проспективно). Резолюция, в charter:
легитимно, если (а) помечен DESIGNED (Lab уже так делает) и (б) субъект — РЕАЛЬНАЯ ожидающая RTM-задача,
не сфабрикованная. Fork-1: агент первым — не «дёшево», а **самый он-тезисный тест** (холодный агент по
опроснику+git+спеке = дословно тезис #1); человек — второй якорь. Fork-2: твоё, назвать можешь только ты;
кандидаты из RTM: ClassificationId="ALL" (§36), agent↔BU membership, RTSData_MidnightClear (§ RTM-SEC-001).
