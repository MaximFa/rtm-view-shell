## Часть A — дисциплина

### Q1. «Ничего не произошло»: дошла ли правка?

Присланный текст — сообщения инструмента, а не состояние мира; как доказательство он стоит ноль.
`no changes added to commit` говорит только «индекс равен HEAD», `Everything up-to-date` — только «удалённая
ссылка равна локальной». О моём файле ни одно не говорит ничего.

Состояния мира, дающие ровно этот вывод:
1. Путь игнорируется и не отслеживается (`.coord/inbox/…`, `.coord/sessions/…`): `add` по каталогу молча
   пропускает его — **работа НЕ в репозитории**.
2. Содержимое уже было закоммичено раньше (диск == дерево): **работа В репозитории**, коммитить нечего.
3. Запись не дошла до диска или ушла в другой путь (обрезка маунта, контейнерный путь вместо маунта,
   другая копия файла) — файл на диске равен HEAD, правки нет нигде.
4. Команды выполнены в другом рабочем каталоге / клоне / ветке (`v4`-каталог вместо главного).
5. Коммит сделан во временный индекс (`GIT_INDEX_FILE`) или на другую ветку, а смотрим не туда.

Единственная сверка, которая закрывает вопрос: **`git hash-object <файл>` против `git rev-parse <ветка>:<путь>`**
(а для доставки наружу — `git cat-file -e origin/<ветка>:<путь>` после fetch). Плюс `git cat-file -e`
отличает «нет в дереве вовсе» (п.1) от «есть, но другое» (п.3).

Прогнано сейчас, три разных исхода на трёх файлах:
```
.claude/skills/role-metrics/role-metrics.md disk=024abd0b tree=024abd0b      <- состояние 2: в репо
.coord/rejects.md disk=80c00c9f tree=c1e81814                                <- на диске есть НЕзакоммиченное
.coord/inbox/metrics.md disk=40c089df tree=fatal: Needed a single revision   <- состояние 1: в дереве нет вовсе
```

### Q2. Два предупреждения, которые выглядят одинаково

(а) `.coord/…`, тишина, коммитить нечего. Файл не отслеживается и попадает под `*` в `.coord/.gitignore`;
`add` по каталогу ignored-файлы пропускает молча. **Работа потеряна** — существует в одном экземпляре на диске.
(б) `.claude/…`, «paths are ignored», затем коммит берёт N файлов. Правила игнора **не действуют на
отслеживаемые файлы**: тело уже в индексе, git ругается на правило, а файл добавляет (rc 1 при успехе —
норма «код возврата — не результат», `3638954`). **Работа не потеряна.**

Почему это разные случаи: решает не текст предупреждения, а отслеживается ли путь. Механический различитель:
`git ls-files --error-unmatch <путь>` (отслеживается?) до, и `hash-object` == `rev-parse HEAD:<путь>` после.
```
$ git check-ignore -v --no-index .claude/skills/role-metrics/role-metrics.md
.gitignore:49:.claude/	.claude/skills/role-metrics/role-metrics.md          rc=0  <- правило "совпало"
$ git ls-files --error-unmatch .claude/skills/role-metrics/role-metrics.md
.claude/skills/role-metrics/role-metrics.md                                   rc=0  <- и всё равно отслеживается
$ git ls-files --error-unmatch .coord/inbox/metrics.md
error: pathspec '.coord/inbox/metrics.md' did not match any file(s) known to git  rc=1
```
Цена в обе стороны. Принять (а) за успех — ложно-зелёное: «сделано» про работу, которая умрёт при первой
уборке. Принять (б) за отказ — ложно-красное: повторный коммит, `-f` поверх живого, а в оплаченном случае
`coordinator-0924` **отозвал верный ответ теста** по этому ложному основанию. Ложно-красное дороже.

### Q3. Проверка, которая врёт «да»

Грепнулся маркер — проход ничего не стоит, если:
1. маркер был в файле и ДО правки (нет пары до/после — одно число ничего не доказывает);
2. игла ловит упоминание, а не употребление (документ, описывающий маркер, содержит его же);
3. греп по диску, а вопрос о доставке — диск не стор (незакоммиченное, кэш маунта, чужая копия);
4. правильный файл, неправильное место — урок лёг в `§D`, вставка «перед §D» попала в конец `§C`;
5. греп по не той ветке / не тому рабочему каталогу.
Чтобы стала проверкой: ожидаемое печатается до замера; пара до/после; игла печатается вместе с числом;
отрицательная половина — та же игла на заведомо пустом месте обязана дать 0; источник — стор, а не диск.

Случай `check-ignore -v`. Четыре строки означали «к путям применимо правило игнора» — и ничего про то,

означают обратное — путь ВОЗВРАЩЁН из игнора. Куратор взял вывод инструмента за ответ на вопрос «тело в
