# role-skill standard + promotion gate (Specialist Protocol spine)
> Curator-owned (NORM-CUR-11). The VERTICAL axis: how ONE role keeps + grows its expertise across its own
> re-instantiations. Complements §42 (horizontal coordination). Source spec: .coord/specialist-protocol.md.
> Curator OWNS this standard + audits role-skills ASYNCHRONOUSLY (NOT a per-write gate — that would stall capture).

## Two layers (the cut)
- PERSISTENT (role): `.claude/skills/role-<role>/role-<role>.md` — SURVIVES reap. The worker's notebook.
- EPHEMERAL (incarnation): `.coord/sessions/<slug>.md` — dies at reap (claims/heartbeat/cc_task).
IRON RULE: nothing durable lives ONLY in the ephemeral layer. A lesson is written into the PERSISTENT layer BEFORE
the incarnation ends, or it is lost by design.

## role-skill anatomy
Frontmatter: `role, project, version, last_verified, owner: <role>, reviewer: curator`.
- §A CORE — invariant, HARD CAP ~40 lines, loaded EVERY init. Role rules + the caveat "reality wins — update me" +
  3-7 cardinal truths, EACH source-pinned. If §A can't be read in one breath, weed §B.
  **§A — МЕСТО С НУЛЕВОЙ СУММОЙ (норма 2026-09-20, куратор).** Кап — не пожелание: `§A` грузится
  при КАЖДОМ ините КАЖДОЙ роли, то есть его строки оплачиваются чаще всех прочих в колонии.
  Поэтому **внесение в `§A` обязано сопровождаться прополкой `§A` не меньшего объёма**: вошло N
  строк — вышло N. Возведение урока в `§A` есть ЗАМЕНА, а не дописывание; вытесненное уходит в `§B`
  целиком, без сокращения. Предъявляется парой «до/после» в строках и байтах.
  **Без этого кап становится украшением:** [измерено 2026-09-20] `role-coordinator` 177 строк
  при капе ~40, `role-devops` 115, `role-shell` 52, `role-curator` 44 — то есть нарушен и у автора
  этой нормы. Восемь тел из двенадцати в капе, четыре вне.
  **Пункт, продиктованный оператором дословно, помечается `НЕ ПЕРЕНОСИТЬ` и прополке не подлежит** —
  иначе следующая инкарнация «наведёт порядок» и вынесет в `§B` ровно то, что туда попадать не должно.
  Прополка не отменяется и для него: место под него освобождается за счёт других строк.
- §B LESSONS — append-only, dated, with status. One line each:
  `<date> · <what happened> · <rule> · SOURCE:<commit/journal-ts/log/file:line> · status: active|superseded-by:<id>`
- §C VERIFY — at init: spot-check §A cardinal truths against CURRENT code/artifacts; mismatch -> mark superseded, do NOT act on it.
- §D REFERENCE (optional) — deep material, NOT loaded each init.
  ⚠ Because §D is NOT loaded at init and §C only spot-checks §A, **§D is verified by nothing** — a dead
  path there survives until someone opens the reference by hand (real case: `.coord/protocols/specialist-protocol.md`
  referenced from role-curator §D, absent from `v3`, undetected for ~2 months; it survives only inside the
  FROZEN `migration/bus-snapshot/`). Cheap closure, one line per role: add to §C a check that every path
  named in §D resolves — `git cat-file -e v3:<path>` per path, expected exit 0.
  **This is a SENSOR, not a gate**: it reports into the init report and never blocks. A sensor promoted to a
  mandatory gate becomes the process-creep it exists to detect.

## 4 invariant properties (carried from the working anchor)
1. CO-OWNERSHIP with a reality-node (the role + the code/artifacts; reviewer = curator).
2. "REALITY WINS — update me" caveat is explicit in §A.
3. CORE (invariant) vs PERIPHERY (append-able) separation.
4. SOURCE-GROUNDING, not session narrative (sessions confabulate — verified repeatedly). Every fact pins a source.

## Capture discipline (anti-rot)
- CAPTURE is a MANDATORY lifecycle step (not opt-in): any task that yields a lesson -> append the dated, source-pinned
  lesson to §B BEFORE the task closes. Wired into the CC postamble next to binding-RESULT (§0.6b).
- Status active/superseded only; SILENT editing forbidden (like the journal). Reality-wins caveat. VERIFY at init.
- ROUTING (operator 2026-06-22): EVERY lesson is recorded in §B (append-only) — nothing is 'too small for §B'. A lesson is
  ELEVATED to §A as a source-pinned CARDINAL TRUTH ONLY when it is a CRITICAL AMPLIFIER: a load-bearing invariant that changes
  how the role ACTS at init / high recurrence / high blast-radius. Default = §B; §A is RESERVED for critical amplifiers and stays
  within the ~40-line cap (elevate deliberately; weed §A when it overflows). Capture EVERYTHING in §B; promote ONLY amplifiers.
- Periodically weed §B so §A stays loadable. Writes are native-CC only (mount truncates), via §4-review.
- **ПРОЧИТАННАЯ НОРМА НЕ ЕСТЬ ИСПОЛНЯЕМАЯ (норма 2026-09-20, кандидат `coordinator-0919b`, принят).**
  Форма, чьё исполнение не проверяется, живёт до первой спешки. Предикат ставится ОДИН раз за
  инкарнацию и не превращается в ритуал: **ПЕРВЫЙ отчёт роли после инита разбирается ею самой
  по блокам объявленной формы** — есть ли обязательный блок последним, одна ли строка резюме,
  один ли вопрос. Проверяется то, что роль и так производит; дополнительной работы это не создаёт.
  Повторять на каждом отчёте ЗАПРЕЩЕНО: датчик, возведённый в обряд, сам становится машинерией.
  Оплаченный случай: Н-12 лежала в стандарте, роль привела её в отчёте и нарушила через ход.
- **ГРАНИЦА ЧЕСТНОСТИ — ОТДЕЛЬНЫМ БЛОКОМ, НЕ ОГОВОРКОЙ В ПРОЗЕ (агностическая половина формы
  отчёта, 2026-09-20).** В любом отчёте кому бы то ни было: (а) «что НЕ проверено» стоит отдельным
  блоком, а не растворяется в тексте; (б) **чужая находка называется чужим именем, свой промах —
  своим.** Порядок остальных блоков — дело роли и её оператора; эти две вещи не зависят от роли.

## Lifecycle (vertical, brother of the §42 horizontal lifecycle)
INIT/HANDOFF (wake ritual): (1) §0.2 integrity-check; (2) read role-<role>.md §A CORE — expert from line 1;
(3) §C VERIFY vs current code, mark stale; (4) read role charter + re-claim territory (§42.2) + read own inbox.
WORK: under coordination discipline (claims, binding .coord/cc/<role>.md, §4-review, native-CC, commit.lock).
CAPTURE: mandatory, as above. HANDOFF/REAP: ephemeral layer may die; the PERSISTENT role-skill carries forward; a
fresh incarnation reads it and is ALREADY expert.

## Scope tiers + PROMOTION GATE (PREVENT-BEFORE / fail-closed — hold the bar hardest here)
- Specialist + coordinator role-skills = PROJECT-scoped. Curator = AGNOSTIC.
- **DEFAULT-DENY** (mirrors AD AUTHZ-03): a lesson stays PROJECT-scoped BY DEFAULT. It does NOT enter the agnostic
  curator skill until the gate is AFFIRMATIVELY satisfied with PINNED evidence. No silent promotion. The agnostic tier
  is **append-ONLY-AFTER-PROOF**, never append-then-audit.
- **TWO-KEY promotion:**
  1. The proposing role marks a CANDIDATE in its project role-skill (`status: promotion-candidate`) — it STAYS
     project-scoped meanwhile.
  2. The CURATOR promotes to the agnostic tier ONLY after confirming, with evidence PINNED in the entry: (a) substrate-
     level proof (mount / git / protocol), OR (b) >=2 INDEPENDENT occurrences, each cited with a commit/journal pin FROM
     EACH project. Unproven -> stays project-scoped. A single-domain pattern is NEVER promoted (that path IS the
     cross-domain contagion vector; over-generalization = contamination).
- The async curator audit is a SECONDARY backstop (catch slips), NOT the primary gate. The gate stops the contagion
  BEFORE it crosses, not after it crossed.

## §C VERIFY — WRITE-TIME GATE (NORM-CUR-11c, peer-review Маяк)
A broken verifier is WORSE than none: a §C check that FAILS against correct code FALSELY marks a TRUE truth superseded —
defeating the anti-rot purpose (real defect: role-backend §C#1 grep `CREATE PROCEDURE`=2 vs `CREATE OR REPLACE PROCEDURE`=15).
- Every §C VERIFY check MUST be EXECUTED ONCE at AUTHORING time and confirmed to return its EXPECTED result BEFORE the role-skill
  is committed. A §C line that does not pass against the CURRENT code at write-time does NOT ship.
- §4-REVIEW REJECT item: any §C check not run-green at authoring -> verdict REVISE, not PASS. (Mirrors cold-start "from artifacts":
  do not ship a self-check you did not run, same as you do not ship a truth you did not pin.)
- When §C later FAILS at init, treat it as a SIGNAL the code drifted (or the check needs updating) — investigate; do NOT blindly
  supersede a truth on a check you never proved correct.

## Local-validation gate (AGNOSTIC, curator-blessed 2026-07-02)
LOCAL-VALIDATION GATE: nothing moves forward until the commit is validated by a LOCAL RUN on the REAL app — not a PoC/harness/component/object-store alone. Object-store verifies WHAT shipped; local validation verifies it WORKS (TWO floors). CODE/ship roles (backend/shell/dba/devops/qa/test) PERFORM the local validation; GATE roles (curator/coordinator/security) REQUIRE local-validation evidence BEFORE greenlight. Complements NORM-CUR-13 (object-store = truth for what's committed). · SOURCE: operator 2026-06-26; pins T1 9734252 (object-store-verified-but-broken-in-prod), Garnet INC-001d (PoC-harness-only).

## Test-gate (AGNOSTIC kernel, curator-blessed 2026-07-02)
TEST-GATE: in a MULTI-PROJECT solution, building or running ONE project does NOT run the tests — they are SEPARATE build targets. "The app builds/runs" NEVER implies "the tests pass". A green test-gate REQUIRES an ACTUAL test-run RESULT with COUNTS (failed=0), never inferred; a missing/absent test result = HARD STOP. Corollary: a change to a public contract (signature/ctor/const/public member) MUST update its tests in the SAME unit of work, else the test project silently drifts (undetected until a full test build). This is the MIDDLE verification floor: object-store (NORM-CUR-13 — WHAT shipped) → test-gate (tests PASS, counts) → local-validation-gate (app WORKS on the real run). Code/ship roles RUN+report counts; GATE roles REQUIRE+verify the numbers. · SOURCE: operator 2026-07-02, RTM 62-error test-project-drift root cause; substrate = build-graph topology (test projects not referenced by the app target).


## BODY INTEGRITY — норма 2026-08-29 (Н-6…Н-9, куратор + координатор)

Роль-скилл — единственный ПОСТОЯННЫЙ слой роли и грузится при каждом ините.
Цена: `role-coordinator.md` нёс 1913 нулевых байт 57 дней и три коммита поверх; содержимое дыры
текстом не существовало никогда и из стора не восстанавливается.

**Н-6. После ЛЮБОЙ записи в роль-скилл — проверка по БАЙТАМ, до коммита.**
`NUL == 0` · первые 3 байта ≠ `EF BB BF` · `CR == 0` · прирост размера сходится с дописанным.
**Счёт строк доказательством не является:** дыра в 1913 байт не меняет счёт строк вообще.

**Н-7. Сенсор целостности — при ините, ПО ОБОИМ ТЕЛАМ.** Дыра сначала ложится НА ДИСК и лишь потом
уезжает в объект, поэтому стора мало. Три строки, ожидание `0 / 0 / равны`:
```
python3 -c "d=open('<скилл>','rb').read();print(d.count(b'\x00'))"        -> 0   (диск)
git show v3:<скилл> | tr -d -c '\000' | wc -c                              -> 0   (стор)
git hash-object <скилл>  ==  git rev-parse v3:<скилл>                      -> равны
```
**Это СЕНСОР, а не гейт.** Красный не блокирует подъём — идёт в отчёт инита и оператору. Расхождение
диск↔стор объявляется вслух с причиной; молча грузиться с дрейфующего тела нельзя.

**Н-9. Новый роль-скилл не заведён, пока не прогнана Н-6 и не назван sha.** «Я добавил» — не поставка;
поставка — `DELIVERED <sha>`.

**Файл с NUL классифицируется как БИНАРНЫЙ — поэтому `§C` не формулируется через показ строки.**
Счётные проверки по такому телу остаются зелёными, а показывающие строку немеют: проверка выглядит
пройденной и не показывает ничего.

**Формулировка нормы едина и живёт ЗДЕСЬ.** Роль со своим вариантом этой проверки приводит его к этой
формулировке: расхождение формулировок одной нормы хуже, чем чужая формулировка.
Цена и замеры — `standard-evidence.md`, запись 2026-08-29.

## ПРОИСХОЖДЕНИЕ УТВЕРЖДЕНИЯ — норма 2026-09-13 (Н-11, координатор → куратор, по требованию оператора)

Цена: к верному числу («строк нет с 11.09 16:21») был приклеен невымеренный вывод о поломке адаптера;
объяснение оператора — праздники — сходится с теми же числами и не требует ни одной поломки.
Построенный на этой связке предикат приёмки дал бы КРАСНОЕ в праздник при исправном канале.

**Н-11. Каждое утверждение несёт метку происхождения В САМОМ ТЕКСТЕ:**
`[измерено: <чем>]` · `[со слов оператора: <дата>]` · `[вывод]`.

1. **Утверждение о МИРЕ бывает только измеренным или операторским.** Календарь, трафик, нагрузка,
   чужие руки, состояние вне нашей зоны, аккаунт, топология — `[вывод]` там не бывает вовсе.
2. **`[вывод]` не может быть основанием решения с ценой.** Годится как гипотеза и как повод пойти
   измерить; как основание отката, деплоя, эскалации или закрытия пункта — нет.
3. **Подпись выдумки:** «моё объяснение хорошо сходится с числами». У одних и тех же чисел бывает
   несколько объяснений, и побеждает не складное, а то, которое не требует недоказанных событий.
4. **Метка ставится автором, а не читателем.** Утверждение без метки читается как `[вывод]`, то есть
   не является основанием ни для чего.
5. См. также Н-16: предикат приёмки не опирается на величину, которой управляет внешний мир.
Цена и замеры — `standard-evidence.md`, запись 2026-09-13.

прочитанная как `0`, даёт ложно-зелёное или ложно-красное, неотличимое от настоящего.

**Плюс положительный контроль (POSCTL) на каждую иглу по всему корпусу:** игла, которая не находится
НИГДЕ, — это «матчер под сомнением», и её нули находкой не считаются.

**Н-14. Список, на котором стоит предикат, — тоже измерение.** Он предъявляется вместе с командой,
которой получен, и сверяется вторым независимым способом. Предикат, перебирающий список, не может быть
надёжнее списка.

**Н-15. Порядок ветвей есть часть предиката.** «Строк нет» проверяется ДО «счётчик не инициализирован»;
иначе первая же ветвь съедает случай, ради которого писалась вторая.

**Н-16. Предикат приёмки не зависит от величины, которой управляет внешний мир** — трафик, календарь,
чужие люди, — пока оператор не подтвердил, что она сейчас ожидается ненулевой. Иначе праздник,
выходной или тихий час читаются как отказ.

## Н-11б — УНАСЛЕДОВАННОЕ УТВЕРЖДЕНИЕ (дополнение к Н-11, 2026-09-13)

> Автор — `devops-0912`, найдено в первом же применении Н-11, принято куратором `gmail` 2026-09-13.

Н-11 знает три метки происхождения и запрещает утверждению о МИРЕ носить `[вывод]`. Она молчала о
третьем случае: утверждение о мире, **взятое из собственной записи прошлого хода**. Оно не `[измерено]`
— сейчас не снято; и не `[вывод]` — не выведено, а принято. Метка:

```
[не измерено в этом пробуждении: источник — <файл/запись>, <дата>]
```

Правила те же, что у `[вывод]`: такое утверждение **не бывает основанием дорогого решения**. Нужно
решение — сначала замер. Метка обязана нести источник И дату: унаследованный замер стареет, и дата —
единственное, что об этом говорит.

Зачем отдельная метка, а не одна из трёх. `[измерено]` здесь было бы ложью. `[вывод]` — маскировкой:
он прячет тот факт, что утверждение о мире у тебя ЕСТЬ, просто чужое во времени. Пересказ собственной
вчерашней записи не делает её сегодняшним замером.

Типовой отказ, который метка ловит: после паузы или компакции роль перечисляет состояние мира связно и
уверенно, и всё перечисленное — вчерашнее. Признак: связное объяснение без единой команды.

## GIT ЧЕРЕЗ МАУНТ — норма 2026-09-17 (`PR234-GITBAN-UNSPREAD-01`)

Цена: пишущая команда берёт `.git/index.lock`, мост снять его не может, репозиторий у оператора встаёт намертво.

**КРИТЕРИЙ — МЕХАНИЗМ, А НЕ ИМЯ: может ли команда ЗАПИСАТЬ `.git/index`.**
```
ЗАПРЕЩЕНО через маунт:  status · add · diff · commit · stash · checkout · reset · restore
РАЗРЕШЕНО:              log · show · cat-file · rev-parse · rev-list · ls-tree · ls-files
                        hash-object (без -w) · merge-base · check-ignore · describe
```

**Запрет держится ПО ИМЕНИ, хотя механизм уже, и это сделано намеренно.** `git diff A B` индекс не пишет —
запрет шире механизма. Сужать нельзя: роль, выводящая себе разрешение в момент употребления («мне только
посмотреть»), ошибается именно там, где цена — вставший репозиторий. Кому нужно сравнение —
`git show <sha>:<путь>` в два файла и `diff` файлов, git при этом не участвует.

**`GIT_OPTIONAL_LOCKS=0` НЕ спасает** [измерено 2026-09-17]: команда зависла и была убита по таймауту.

**Правило о правилах, отсюда:** обязательное для ВСЕХ живёт в агностическом слое. Норма, обязательная для

Живость НЕ наблюдаема из файловой системы: файл фиксирует ЗАЯВЛЕНИЕ сессии, а не её жизнь.

## КОНЕЦ ФАЙЛА — ЭТО `§D`. Норма 2026-09-19 (кандидат `coordinator-0919b`, ПРИНЯТ)

**Дефект не в модальности, а в дописывании.** Урок или обязанность попадают в последнюю секцию файла
НЕ ВЫБОРОМ, а тем, что «дописать» на любом носителе означает «в конец», а порядок секций роль-скилла
ставит `§D` последней. **Секцию никто не выбирал.** Поэтому «куда дописывать» — часть нормы.
Цена: три роли порознь нашли у себя уроки, НАПИСАННЫЕ как `§B` и ЛЕЖАЩИЕ в `§D` — в секции,
которую инит велит не грузить; у одной там был весь сентябрьский корпус.

**Норма.** Секция, исключённая из загрузки при ините, обязана быть последней по ссылкам и ПЕРВОЙ ПО
ПУСТОТЕ: в ней не может оказаться ничего, что кто-то дописал. Дописывание урока адресуется секции
ПОИМЕННО, а не концу файла.

**Сенсор — счёт УРОКОВ по секциям, а не модальностей.** Модальность была симптомом, урок в `§D` — болезнью.

⚠ **СЕНСОР ОБЯЗАН ПЕЧАТАТЬ СВОЮ ИГЛУ.** Игла, не предъявленная вместе с числом, делает число
непроверяемым: счётчик уроков дал ложный ноль при десяти лежащих уроках, потому что игла не учла дефис.

⚠ **Перенос делается ДОСЛОВНО.** Переписывать модальность — лечить симптом. И вторая ловушка:
вставка «перед началом `§D`» попадает в КОНЕЦ `§C`, а не в `§B`. **Граница принадлежит соседу —
дописываю к границе, проверь, чья она.**
Цена и замеры — `standard-evidence.md`, запись 2026-09-19 (§D).

## МЕТКА ВРЕМЕНИ — ТОЖЕ ПИН. Норма 2026-09-19 (дефект куратора `curator-0611`, цену заплатила соседняя колония)

**Норма.** Метка времени в любом блоке шины, вердикте или письме **снимается командой
(`date -u`) и вставляется из вывода**. Набранная по ощущению прошедшего времени — подделка,
даже если ошибка в минутах.

**Почему это не мелочь.** Метка выглядит как оформление, а работает как пин: по ней двигаются
курсоры непрочитанного. Пин, который не похож на число, не проверяют — и он проезжает мимо
дисциплины, заведённой ровно против этого.

**Цена, уплаченная не автором:**
```
[измерено] фактическое время: 2026-09-19T22:02Z
[измерено] метки на моих блоках в чужом ящике: 2026-09-20T01:0xZ · 01:3xZ · 02:0xZ · 02:3xZ
           -> до ЧЕТЫРЁХ ЧАСОВ вперёд, и на сутки вперёд по дате
следствие у принимающей стороны: курсор ящика ушёл в будущее на ~2.5 часа;
           два блока ЕЁ СОБСТВЕННЫХ ролей (20:19Z, 20:20Z) оказались ПОД курсором,
           счётчик непрочитанного дал 3 при 5 по позиции
```
**И второй, более дорогой слой:** принимающая сторона поставила диагноз «у них часы впереди».
Диагноз ложный — часы не расходились, метки были сочинены. **Подделка, принятая за свойство
среды, порождает у соседа ложную модель мира, которую он будет применять и после исправления.**
Поэтому обнаруживший подделку обязан не только исправить метку, но и отозвать чужой диагноз.

**Мера принимающей стороны, принята симметрично:** курсор ящика двигается только по СВОИМ
блокам; межколонийный блок в сдвиге курсора не участвует, его прочтение фиксируется строкой
`peer-read: <метка чужого блока>` в `colony-switch-peer.md`. Она защищает и от настоящего
расхождения часов между машинами — то есть нужна и после устранения причины.


## ВЕЛИЧИНА НЕСЁТ ПУТЬ, А НЕ ПРОЗВИЩЕ. Норма 2026-09-19 (поймано соседней колонией через канал)

**Норма.** Число, предъявляемое кому-либо, сопровождается ПУТЁМ предмета, а не его разговорным
именем. `стандарт`, `свод`, `профиль`, `реестр` — прозвища; в колонии их носят по два-три предмета.

**Цена, оплачена в тот же вечер:** я предъявил «стандарт `e6f002ab` (54 173 B)», имея в виду
`.coord/protocols/role-skill-standard.md`. Принимающая сторона перемерила `colony-switch-standard.md`
(тоже «стандарт») и получила `f7c196a9` / 36 590 B. **Оба замера были верны, предметы разные.**
Проверяющий заподозрил несходящееся число там, где сходилось всё.

**Почему это дороже, чем выглядит.** Сосед поступил образцово — назвал расхождение сразу,
причину НЕ назвал, попросил перемерить. Но сам факт ложной тревоги тратит ход обеих сторон
и, главное, **подтачивает доверие к сходящимся числам**: после двух-трёх таких проверяющий
начинает считать несходимость нормой канала.

**Форма предъявления:** `<путь> · <размер> B · <hash-object|rev-parse> <хэш>`. Прозвище допустимо
в тексте объяснения, но не в строке, которую другая сторона будет перемерять.

**Смежное, из того же обмена (мера стороны B, принята):** в блок идёт ВЕЛИЧИНА с командой;
ПРИЧИНА — только со своим замером, иначе пишется «замера причины нет». Диагноз без замера
отзывается БЛОКОМ, а не поправкой в переписке: он живёт в носителях принимающей стороны
и переживает извинение.

⚠ **И встречное наблюдение к их же норме:** величина, снятая командой и затем ЗАМАСКИРОВАННАЯ
при печати (`22:0xZ` вместо `22:09Z`), перестаёт быть замером — проверить её нельзя,
а выглядит она как измеренная. Маскировка допустима только там, где точность не предъявляется
как доказательство.


## ⛔ ПРИВЯЗКА К ПРЕДМЕТУ: МЕХАНИКА РАЗБИРАЕТСЯ С ДВУХ СТОРОН. Норма 2026-09-24, ЧП-разбор

**Дефект, который норма закрывает.** Вся прежняя дисциплина отвечает на вопрос **ВЕРНО ЛИ ИЗМЕРЕНО**
и ни одной проверкой не спрашивает, **ПОНИМАЕТ ЛИ РОЛЬ ПРЕДМЕТ, который измеряет.**
Это опаснее кривого предиката: кривой предикат даёт красное, и его ловят обе стороны, а **вердикт,
выданный без знания механики, выглядит как нормальный вердикт** — с областью, единицей, контролями —
и проходит все наши проверки, потому что все они про измерение. Специалист исполняет добросовестно,
и правится не то место.
Цена: четыре случая за одни сутки, во всех предикат был ПРАВИЛЬНЫЙ; трижды остановлено специалистом
и оператором, один раз спасло только то, что исполнитель не успел.

**НОРМА.** Перед выдачей единицы механика предмета разбирается **С ДВУХ СТОРОН**:
```
(1) как это НАСТРАИВАЕТ пользователь  — путь и строки в интерфейсе/конфиге
(2) как это ПРИМЕНЯЕТ код             — путь и строки в реализации
обе стороны ПРЕДЪЯВЛЯЮТСЯ в письме исполнителю, путями и строками, а не пересказом
```
Единица без такого блока НЕ ВЫДАЁТСЯ. Если одну из сторон установить не удалось — **это не единица,
а вопрос оператору.** Отрицательная половина: блок, в котором обе стороны указывают в один и тот же
файл одной и той же ролью, механику не разбирает — он её имитирует.

**Смежная норма, из того же разбора:**
> **Оговорка, называющая непроверенным то, на чём стоит решение, — не честная граница,
> а признание, что основания нет.**
Назвать непроверенную область — достоинство, пока она НЕ НЕСУЩАЯ. Проверяется вопросом:
**лежит ли названное непроверенным под выводом?**

**Чего норма НЕ требует.** Не требует знать продукт целиком перед каждым ходом — это невыполнимо
и породило бы добросовестную ложь. Требует ровно двух сторон ТОГО предмета, которого касается единица.

**Кто решает о продукте.** Облик, смысл, приоритет и отказ от единицы — решение ОПЕРАТОРА. Роль приносит
развилку с ценой обеих сторон и своё мнение, но не объявляет решение. Продуктовое решение, объявленное
без строки «несу оператору», — дефект; ловится обходом собственных писем роли.
Цена и замеры — `standard-evidence.md`, запись 2026-09-24 (привязка к предмету).

## ⛔ КОЛОНИЯ НЕ ИМЕЕТ ВЕРСИЙ ПРОДУКТА. Норма 2026-09-24 (по решению оператора, ЧП-разбор)

**Правило.** `.coord` и `.claude` — это колония: шина, слаги, протоколы, тела ролей, приборы.
У них НЕ БЫВАЕТ версии под новый дизайн или новую версию продукта. На любой продуктовой ветке
координационный слой обязан быть **побайтово равен** основной ветке. **Продуктовая ветка несёт продукт.**
Уточнение [со слов оператора: 2026-09-25]: «служебное в v3, продукт в v4» — коммиты колонии идут
только в основную ветку; расхождение «только v3» по служебным путям ожидаемо, а не дефект.

**Предикат (обе стороны, при заведении ветки и при возврате к ней):**
```
сравнить деревья двух веток по .coord и .claude       ожидание: расходится 0, односторонних 0
отрицательная половина: тот же предикат по src/       обязан показать расхождение,
                                                       иначе он сравнивает не то
```
Цена: ветка, заведённая в отдельном рабочем каталоге, унесла с собой колонию — 16 тел настоящей работы
оказались заперты в ветке, а роль, поднятая в том каталоге, прочла бы стандарт без свежей нормы.

**⚠ И второе, что делает это опаснее, чем выглядит: ЯЩИКИ НЕ ТРЕКАЮТСЯ ВООБЩЕ**
(`.coord/.gitignore` = `*`). Новый рабочий каталог получает **пустую шину** — не копию, а пустоту:
переписка, стопы и незакрытые вопросы остаются в старом каталоге и невидимы в новом, и наоборот.
Сравнение деревьев этого НЕ ПОКАЖЕТ: в хранилище ящиков нет.
**Отсюда: при заведении нового рабочего каталога шина решается ДО первой записи.** Живёт она
в одном экземпляре; роль, севшая в новый каталог, работает со своей веткой, но пишет в ту же шину.

**Что проверять при заведении ветки продукта — три вопроса, все до первой единицы:**
1. Где шина? Один экземпляр, и он назван путём.
2. Координационный слой равен основной ветке? Предикат выше, обе половины.
3. Кому из ролей менять каталог, и знают ли они об этом? Роль работает там, где её тела и её ящик.
Цена и замеры — `standard-evidence.md`, запись 2026-09-24 (версии продукта).

## КОД ВОЗВРАТА — НЕ РЕЗУЛЬТАТ ОПЕРАЦИИ. Норма 2026-09-24 (случай `coordinator-0924`, разбор куратора)

**Норма.** Предикат строится на РЕЗУЛЬТАТЕ операции, а не на её коде возврата. Ненулевой `rc`
и «операция не выполнена» — разные величины, и их совпадение надо доказывать, а не предполагать.

**Оплаченный случай, две стороны одного дня:**
```
git add без -f на ОТСЛЕЖИВАЕМОМ теле под .claude/ печатает
«The following paths are ignored … Use -f», возвращает rc 1 — и ФАЙЛ ДОБАВЛЯЕТСЯ
[измерено] коммит 3638954: предупреждение напечатано, в коммите 2 файла, оба вошли
[со слов coordinator-0924] его бокс: «rc 1, коммита не было, но файл лёг в индекс по пину»
```
Скрипт принял `rc` за отказ и остановился при успешной операции — **ложно-красное от инструмента.**
Та же ошибка с другой стороны стоила куратору хода утром: предупреждение git об игнорировании
было прочитано как «тело не вошло в ветку».
**Ответ на «вошло ли тело в ветку» даёт только `rev-parse` против `hash-object`.**

⚠ И вторая половина случая: `coordinator-0924` на этом основании ОТОЗВАЛ свой верный ответ
вступительного теста. **Отзыв верного утверждения по ложному основанию — такой же дефект,
как ложное утверждение**, и ловится он тем же: перемером, а не доверием к раскаянию.

## ПРОГОН НА ПРОДУКТОВОЙ ВЕТКЕ КОММИТИТ ТОЛЬКО ПУТИ ПРОДУКТА. Норма 2026-09-24 (кандидат `coordinator-0924`, принят)

**Правило.** Прогон на продуктовой ветке коммитит ТОЛЬКО пути продукта. Прибор живёт в каталоге
замеров ЕДИНСТВЕННОЙ шины и не отслеживается; числа доказательства уезжают в сообщение коммита.
Прибор, который нужен как инструмент, коммитит РОЛЬ-ВЛАДЕЛЕЦ на основной ветке, отдельным
коммитом — не прогоном единицы продукта.

**Предикат, две половины, потому что первая слепа:**
```
ПРИ ВЫДАЧЕ — по ФОРМЕ, не по игле: промпт прогона несёт ЯВНЫЙ список путей коммита
   (строки `git add -- <путь>`); требуется: таких строк >= 1 И пересечение с .coord/ и .claude/ = 0.

ПРИ ПРИЁМКЕ — структурно, по стору: пути .coord и .claude, изменённые коммитом прогона

   даже если первая половина зелёная.
```
**Почему обе.** Автор кандидата сам предъявил слепоту первой: в промпте `userset` строк `git add`
НЕТ ВОВСЕ — коммит прибора велен ПРОЗОЙ, и наивная игла дала 0 при реальном нарушении.
Структурный счёт поймал: `b0fcf4b -> 1` (`.coord/measure/userset-0924/probe_css_cascade.py`),
контроль на соседних коммитах `1d83004 -> 0`, `6141aa1 -> 0`.

## ⛔ ПРОГОН НЕ СВИДЕТЕЛЬСТВУЕТ О СЕБЕ. Норма 2026-09-25 (кандидаты `shell-0919b` и `coordinator-0924`)

**Общая причина четырёх дефектов одних суток:** отчёт прогона о собственном процессе принимался за
измерение. Прогон честен — он пишет то, что намеревался сделать; но написанное намерение и совершённое
действие это две величины, и совпадение надо доказывать.

**1. Запись в шине засчитывается только `grep` РОЛИ по правильному файлу, названному путём.**
Отчёт, в котором путь верен, а действие ушло в другое место, **по тексту неотличим от правильного.**
Значит проверяется предмет, и проверяет его НЕ автор отчёта.

**2. Время в шину берётся только из `date -u` и вставляется из вывода.** Сочинённая метка двигает
курсоры непрочитанного и прячет чужие блоки — цена уже уплачена соседней колонией.

**3. Запись в шину начинается с перевода строки.** Годная игла: `(?<![\n#])## 20\d\d`, позиция 0
исключена. `^## ` склеенный заголовок НЕ ВИДИТ — счёт по началу строки занижает реестр молча.
⚠⚠ **ДВЕ ОШИБКИ ОДНОГО КЛАССА, ВТОРАЯ ДОРОЖЕ.** Автор кандидата назвал ОДИН случай: **случай,
найденный глазами, называет место; количество называет только обход.** Куратор обошёл негодной иглой
и завысил — на своём файле в семь шестых, на соседнем дал бы 51 при 0 настоящих.
**Обход без отрицательной половины на ЗАВЕДОМО НЕ-СЛУЧАЕ называет количество, которого нет.**
Останавливаться на первом случае — занижать; обходить негодной иглой — завышать и отправлять чинить
исправное, причём с числом, которое выглядит измеренным.
**Правило: у иглы обхода обязан быть прогон на файле, где искомого заведомо НЕТ, с ожиданием 0.**

**4. `done` допустим только при предъявленной строке остановки.** Нет строки `STOP-предикат: N, STOP=M` —
статус `incomplete`, не `done`. Форма остановки ловит «увидел красное и пошёл дальше»; она НЕ ловит
«не мерил вовсе». Это разные отказы, и второй тише.

**5. Прогон обращается к координатору только через своего специалиста и только слагом из
`.coord/sessions/`.** Адресат без слага в реестре — письмо ниоткуда, отвечать на него некому.
Цена и замеры — `standard-evidence.md`, запись 2026-09-25 (прогон о себе).

## ⛔ ПЕРЕНОС БЕЗ НАЗВАННОГО НАПРАВЛЕНИЯ — УНИЧТОЖЕНИЕ. Поправка 2026-09-25, дефект куратора

**Что случилось.** Норма «равенство слоёв — ритм» велела нести слой тем же ходом — верно. Предикат под
ней отвечал на вопрос «расходятся ли» и НИКОГДА на вопрос «какая сторона свежее». Куратор подставил
ответ из привычки: свежая та, где он сидит. Цена — **75 строк чужой работы**, включая два слова
оператора дословно.

**Почему это дороже обычного ложно-зелёного.** Ложно-зелёное обычно ПРОПУСКАЕТ дефект. Здесь проверка,
не различающая направление, **сама создала** тот ущерб, от которого ставилась: единственный экземпляр
работы был уничтожен действием, предпринятым ради его сохранности.

**НОРМА.**
```
1. Перед переносом расхождение меряется В ОБЕ СТОРОНЫ ПОИМЁННО:
   что есть у A и нет у B, и что есть у B и нет у A. Оба числа печатаются, даже нулевые.
2. НАПРАВЛЕНИЕ называется вслух до действия. Перенос без названного направления не делается.
3. Если расхождение двустороннее — переноса нет вообще: есть СВЕДЕНИЕ, и делает его владелец тел.
4. Несовпадение добавленных и удалённых строк в выводе коммита переноса — СИГНАЛ ОСТАНОВКИ,
   а не деталь вывода. «Удалений больше нуля» при переносе означает, что что-то затёрто.
5. Перед записью в чужой рабочий каталог каждый путь сверяется «диск против дерева».
   Расхождение — STOP, а не перезапись: незакоммиченное чужое существует в одном экземпляре.
```
**Отрицательная половина нормы:** после переноса игла по содержимому, бывшему ТОЛЬКО на стороне-
источнике и на стороне-приёмнике, обязана вернуть одинаковые числа с обеих сторон. Равенство блобов
этого не показывает — оно одинаково зелёное и при сведении, и при затирании.

⚠ **Что спасло в этом случае:** строка «90 удалений при 47 добавлениях» в выводе коммита не была принята
за нормальную. **Сигнал был в выводе с самого начала и не требовал никакого прибора.**
Цена и замеры — `standard-evidence.md`, запись 2026-09-25 (перенос).

## ⛔ ГЕЙТ ЖИВЁТ У ТОГО, КТО МОЖЕТ ПРОВЕРИТЬ. Норма 2026-09-25 (кандидат `coordinator-0924`, принят)

**Правило.** Требование, адресованное тому, чьё исполнение мы проверить не можем, — **не гейт,
а пожелание.** Проверка переносится из промпта прогона в БОКС: после прогона бокс сам ищет
в блоке шины обязательные строки, печатает отсутствующие и `STOP`; сборку и тесты бокс снимает
своей командой. **Прогон перестаёт быть единственным свидетелем.**

**Цена: три случая за одни сутки, норма была написана в промпте и не исполнилась ни разу.**
```
[измерено curator-0611 2026-09-25T04:24Z, игла по сообщениям коммитов]
669bcac (backend) · 51cb8b9 (backend) · ff47176 (shell, промпт ceba1a6e нёс ПОЛНУЮ форму)
   STOP 0 · dotnet 0 · шина 0 · самопроверка 0   — во всех трёх
положительный контроль иглы: 3538b71 -> 1 · f4cffad -> 1 · 68b1840 -> 1   (игла видит слово)
```
Третий случай решающий: промпт нёс форму целиком и был принят по §4. **Текст требования
не доходит до действия** — значит дефект не в формулировке и не в исполнителе, а в том,
КОМУ поручена проверка.

**Отличать от «формы остановки».** Форма остановки ловит «увидел красное и пошёл дальше».
Эта норма ловит «не мерил вовсе» — отказ тише, потому что у него нет следа: отсутствие строки
выглядит как её ненужность.

**Обобщение, которое стоит помнить шире переноса проверок:**
каждый раз, когда мы усиливали ТЕКСТ требования, отказ повторялся. Он прекращается только тогда,
когда меняется АДРЕСАТ проверки. Усиление формулировки — самый дешёвый и самый частый способ
ничего не изменить.


## ⛔ СВИДЕТЕЛЬСТВО ПИШЕТ НЕ ТОТ, КОГО ОНО УЛИЧАЕТ. Норма 2026-09-25 (кандидат `shell-0919b`, поддержан `coordinator-0924`, принят)

**Что довершает эта норма.** Предыдущая перенесла ПРОВЕРКУ к тому, кто может проверить, —
и отказ стал видимым. Четвёртый случай за сутки показал, чего ей не хватает:
```
[измерено curator-0611 2026-09-25T05:00Z] коммит 7931075, последний блок в cc/shell.md: 7 строк
   STOP 0 · dotnet 0 · подписи 0 · колония 0 · слово RESULT 1
   бокс проверку ПЕЧАТАЛ — пропуск был назван и всё равно не заполнен
положительный контроль по всему файлу: STOP 3 · dotnet 32 · RESULT 92 — иглы видят
```
**Норма ловит пустоту, но не заполняет её.** Заполнять по-прежнему должен тот, кого отчёт уличает.

**НОРМА (редакция 2026-10-05, см. поправку в конце секции).**
**Свидетельство пишет не тот, кого оно уличает.** От прогона остаются код и коммит; его слово о себе
доказательством не является.

**⚠ ОБРАТНАЯ СТОРОНА, БЕЗ КОТОРОЙ НОРМУ БРАТЬ НЕЛЬЗЯ.** Бокс становится ЕДИНСТВЕННЫМ свидетелем,
а пишем его мы. Доверие не исчезло — оно переехало. Значит:
1. у бокса обязана быть **отрицательная половина**: прогон, заведомо нарушивший форму, обязан дать
   красное. Бокс, ни разу не вернувший красного, — не свидетель, а украшение;
2. бокс печатает **иглу вместе с числом** — иначе его ноль неотличим от ноля слепого прибора;
3. **бокс не судит.** Он печатает величины; вердикт выносит роль, читающая их. Свидетель,
   выносящий приговор, — это тот же дефект на ступень выше.

**Чего норма НЕ отменяет.** Прозу прогона о том, ЧТО он делал и почему, — её не измеришь, и она
остаётся за ним. Отменяется только его слово о СЕБЕ как доказательство.

### ⛔ ПОПРАВКА 2026-10-05: СВИДЕТЕЛЬ — НЕ ВТОРОЙ ПРОГОН, А СЛЕД, КОТОРЫЙ ЧИТАЕТ ДРУГОЙ

Первая редакция сажала свидетеля во ВТОРОЙ прогон (пост-бокс оператора). Он не записал блок
**3 раза из последних 5 единиц**. То есть норма посадила гейт туда, где его исполнение снова зависит
от прогона, — ровно то, что запрещает «ГЕЙТ ЖИВЁТ У ТОГО, КТО МОЖЕТ ПРОВЕРИТЬ». Дефект мой:
я написал правило, нарушающее соседнее правило, и год цена была бы та же — ложное зелёное по молчанию.
Побочно это стоило оператору двух обращений на одну единицу вместо одного.

**Редакция.** Свидетель — не второй исполнитель, а **СЛЕД, КОТОРЫЙ ЧИТАЕТ НЕ АВТОР**. Бокс один.
Независимость держится на том, что проверяющий берёт величину САМ, из источника, которым автор
не управляет:
```
содержание  -> координатор читает из объектного хранилища (git show/cat-file), не из отчёта
сборка/тесты -> машинные файлы в .measurements/, координатор читает файл, а не строку отчёта
экран/сервер -> величина, которую проверяющий может СНЯТЬ ЗАНОВО сам (версии в отданном HTML,
                ответ живой службы). Замер, который заново не снять, следом не является
```
Нет следа — единица не принята. Роль за прогон блок не дописывает.

**⚠ Третья опора — слабая, и вот граница.** «Роль посмотрела на стенде» — это снова слово о себе,
если после него не остаётся ничего, что перепроверяется. Годится только то, что проверяющий
воспроизводит своей командой либо что легло файлом. Скриншот без команды, которой его повторить, —
проза, а не след.

**⚠ ПРИБОР ОБЯЗАН ДОКАЗАТЬ, ЧТО ОН БЫЛ ЖИВ В МОМЕНТ ЗАМЕРА.** Замер в браузере засчитывается только
при `visibilityState: visible` и фокусе: фоновая вкладка притормаживается и дала ложное зелёное
[`shell-0919b`, 2026-10-05]. Шире: у прибора, который среда вправе усыпить, притормозить или
оборвать, положительный контроль обязан подтверждать не только «ответ получен», но и
**«прибор работал тогда, когда мерил»**.
Цена и замеры — `standard-evidence.md`, запись 2026-10-05.


## ВОПРОС, ОТВЕЧАЕМЫЙ ЗАМЕРОМ, — НЕ ВОПРОС ОПЕРАТОРУ. Норма 2026-09-25 (слово оператора, агностическая половина)

[со слов оператора: 2026-09-25] «ничего не меняем кроме визуала. если кто-то не помнит как у нас —
проверяет и делает анализ. я не должен быть бутылочным горлом».

**Норма.** Различать РЕШЕНИЕ и ФАКТ.
```
ФАКТ  — «как это сейчас устроено / что там лежит / какое значение по умолчанию»
        -> снимается командой по хранилищу, результат идёт ПИСЬМОМ, а не вопросом
РЕШЕНИЕ — «каким этому быть / что важнее / от чего отказываемся»
        -> несётся оператору развилкой с ценой обеих сторон
```
**Это вторая половина нормы «продуктовое решение — оператора».** Без неё роль, наученная не решать
сама, начинает нести оператору и то, что обязана измерить. Обе крайности одинаково дороги:
роль, решающая за оператора, портит продукт; роль, спрашивающая измеримое, портит его время —
и время это единственный ресурс, которого у него ровно столько, сколько есть.

**Предикат перед вопросом оператору:** назови команду, которой этот вопрос НЕЛЬЗЯ закрыть.
Не назвал — это не вопрос, это незаконченный замер.

## ⛔ ЗАПРЕТ, ЖИВУЩИЙ ТОЛЬКО В ТЕКСТЕ, ПРОИГРЫВАЕТ ИНСТРУКЦИИ СРЕДЫ. Норма 2026-09-26

Среда прогона сама подаёт ассистенту указание подписывать коммиты, и подаёт его с системной рамкой.
Поэтому запрет, исполнение которого держится только на том, что прогон прочитал его в промпте, стоит ноль.

1. **Окно, а не последний коммит.** Запрет стоит на «нигде», значит меряется по всему `BASE..COMMIT`.
   Ноль по одному коммиту — ответ не на тот вопрос, то есть ложное зелёное.
2. **Предикат — разбор трейлеров, не поиск слов.**
   `git log -1 --format=%B <c> | git interpret-trailers --parse | grep -ciE "^(Co-Authored-By|Claude-Session|Generated with):"`
   Поиск по словам на нашем собственном слое врёт всегда: документ, описывающий запрет, содержит его слова.
   Предикат обязан отличать употребление от упоминания.
3. **Гейт — у бокса оператора.** Считает не прогон: он обвиняемый (см. «СВИДЕТЕЛЬСТВО ПИШЕТ НЕ ТОТ, КОГО ОНО УЛИЧАЕТ»).
   Больше нуля — бокс печатает `STOP`.
4. **Свидетель, увидевший нарушение стоячего запрета, печатает `STOP` и ПРЕКРАЩАЕТ работу.**
   Его отрицательная половина — первое действие; блок в шину пишется последним и несёт её результат.

Цена и замеры — `.coord/protocols/standard-evidence.md`, запись 2026-09-26.

## ПРАВИЛО ПАРЫ: СТАНДАРТ НЕСЁТ ПРАВИЛО, `standard-evidence.md` НЕСЁТ ЦЕНУ. 2026-09-26

Стандарт читается ЦЕЛИКОМ при каждом подъёме каждой роли, поэтому в нём лежит правило и одна строка цены.
Разбор — как обнаружено, какими командами, чьи числа, какая проверка соврала — лежит в
`.coord/protocols/standard-evidence.md`. Роль заходит туда, когда правило оспаривают или перепроверяют.

**Почему это не вкусовщина.** Файл на 97 килобайт роль честно не читает: норма «конец файла — это §D»
родилась именно из того, что до конца длинного файла не доходят. Правило, до которого не дочитали,
не работает, как бы хорошо оно ни было обосновано.

**Чем держится от расхождения — двумя гейтами у бокса, не в тексте:**
```
1. каждая ссылка «запись <дата>» из стандарта обязана иметь «## <дата>» в standard-evidence.md
   отрицательная половина: подставить заведомо отсутствующую дату, ожидание — красное
2. правка стандарта и правка доказательств входят в ОДИН коммит; иначе цена остаётся без правила
   или правило без цены
```

⚠ **Игла пишется ПО ТЕКСТУ, а не по памяти о тексте.** Три ложных красных за одни сутки у куратора:
подпись поймана в описании запрета; `^`-якорь сработал на переносе строки; «потеряно» объявлено там,
где текст есть, но обёрнут в бэктики. Перед выводом «не нашёл» игла прогоняется на строке, которая
заведомо есть, — иначе «не нашёл» означает только, что искали не тем.
Цена и замеры — `standard-evidence.md`, запись 2026-09-26 (правило пары).
