# role-skill standard + promotion gate (Specialist Protocol spine)
> Curator-owned (NORM-CUR-11). The VERTICAL axis: how ONE role keeps + grows its expertise across its own
> re-instantiations. Complements §42 (horizontal coordination). Source spec: .coord/specialist-protocol.md.
> Curator OWNS this standard + audits role-skills ASYNCHRONOUSLY (NOT a per-write gate — that would stall capture).

## Two layers (the cut)
- PERSISTENT (role): `.claude/skills/role-<role>/role-<role>.md` — SURVIVES reap. The worker's notebook.
- EPHEMERAL (incarnation): `.coord/sessions/<slug>.md` — dies at reap (claims/heartbeat/cc_task).
IRON RULE: nothing durable lives ONLY in the ephemeral layer. A lesson is written into the PERSISTENT layer BEFORE
the incarnation ends, or it is lost by design.

## role-skill anatomy
Frontmatter: `role, project, version, last_verified, owner: <role>, reviewer: curator`.
- §A CORE — invariant, HARD CAP ~40 lines, loaded EVERY init. Role rules + the caveat "reality wins — update me" +
  3-7 cardinal truths, EACH source-pinned. If §A can't be read in one breath, weed §B.
- §B LESSONS — append-only, dated, with status. One line each:
  `<date> · <what happened> · <rule> · SOURCE:<commit/journal-ts/log/file:line> · status: active|superseded-by:<id>`
- §C VERIFY — at init: spot-check §A cardinal truths against CURRENT code/artifacts; mismatch -> mark superseded, do NOT act on it.
- §D REFERENCE (optional) — deep material, NOT loaded each init.
  ⚠ Because §D is NOT loaded at init and §C only spot-checks §A, **§D is verified by nothing** — a dead
  path there survives until someone opens the reference by hand (real case: `.coord/protocols/specialist-protocol.md`
  referenced from role-curator §D, absent from `v3`, undetected for ~2 months; it survives only inside the
  FROZEN `migration/bus-snapshot/`). Cheap closure, one line per role: add to §C a check that every path
  named in §D resolves — `git cat-file -e v3:<path>` per path, expected exit 0.
  **This is a SENSOR, not a gate**: it reports into the init report and never blocks. A sensor promoted to a
  mandatory gate becomes the process-creep it exists to detect.

## 4 invariant properties (carried from the working anchor)
1. CO-OWNERSHIP with a reality-node (the role + the code/artifacts; reviewer = curator).
2. "REALITY WINS — update me" caveat is explicit in §A.
3. CORE (invariant) vs PERIPHERY (append-able) separation.
4. SOURCE-GROUNDING, not session narrative (sessions confabulate — verified repeatedly). Every fact pins a source.

## Capture discipline (anti-rot)
- CAPTURE is a MANDATORY lifecycle step (not opt-in): any task that yields a lesson -> append the dated, source-pinned
  lesson to §B BEFORE the task closes. Wired into the CC postamble next to binding-RESULT (§0.6b).
- Status active/superseded only; SILENT editing forbidden (like the journal). Reality-wins caveat. VERIFY at init.
- ROUTING (operator 2026-06-22): EVERY lesson is recorded in §B (append-only) — nothing is 'too small for §B'. A lesson is
  ELEVATED to §A as a source-pinned CARDINAL TRUTH ONLY when it is a CRITICAL AMPLIFIER: a load-bearing invariant that changes
  how the role ACTS at init / high recurrence / high blast-radius. Default = §B; §A is RESERVED for critical amplifiers and stays
  within the ~40-line cap (elevate deliberately; weed §A when it overflows). Capture EVERYTHING in §B; promote ONLY amplifiers.
- Periodically weed §B so §A stays loadable. Writes are native-CC only (mount truncates), via §4-review.

## Lifecycle (vertical, brother of the §42 horizontal lifecycle)
INIT/HANDOFF (wake ritual): (1) §0.2 integrity-check; (2) read role-<role>.md §A CORE — expert from line 1;
(3) §C VERIFY vs current code, mark stale; (4) read role charter + re-claim territory (§42.2) + read own inbox.
WORK: under coordination discipline (claims, binding .coord/cc/<role>.md, §4-review, native-CC, commit.lock).
CAPTURE: mandatory, as above. HANDOFF/REAP: ephemeral layer may die; the PERSISTENT role-skill carries forward; a
fresh incarnation reads it and is ALREADY expert.

## Scope tiers + PROMOTION GATE (PREVENT-BEFORE / fail-closed — hold the bar hardest here)
- Specialist + coordinator role-skills = PROJECT-scoped. Curator = AGNOSTIC.
- **DEFAULT-DENY** (mirrors AD AUTHZ-03): a lesson stays PROJECT-scoped BY DEFAULT. It does NOT enter the agnostic
  curator skill until the gate is AFFIRMATIVELY satisfied with PINNED evidence. No silent promotion. The agnostic tier
  is **append-ONLY-AFTER-PROOF**, never append-then-audit.
- **TWO-KEY promotion:**
  1. The proposing role marks a CANDIDATE in its project role-skill (`status: promotion-candidate`) — it STAYS
     project-scoped meanwhile.
  2. The CURATOR promotes to the agnostic tier ONLY after confirming, with evidence PINNED in the entry: (a) substrate-
     level proof (mount / git / protocol), OR (b) >=2 INDEPENDENT occurrences, each cited with a commit/journal pin FROM
     EACH project. Unproven -> stays project-scoped. A single-domain pattern is NEVER promoted (that path IS the
     cross-domain contagion vector; over-generalization = contamination).
- The async curator audit is a SECONDARY backstop (catch slips), NOT the primary gate. The gate stops the contagion
  BEFORE it crosses, not after it crossed.

## §C VERIFY — WRITE-TIME GATE (NORM-CUR-11c, peer-review Маяк)
A broken verifier is WORSE than none: a §C check that FAILS against correct code FALSELY marks a TRUE truth superseded —
defeating the anti-rot purpose (real defect: role-backend §C#1 grep `CREATE PROCEDURE`=2 vs `CREATE OR REPLACE PROCEDURE`=15).
- Every §C VERIFY check MUST be EXECUTED ONCE at AUTHORING time and confirmed to return its EXPECTED result BEFORE the role-skill
  is committed. A §C line that does not pass against the CURRENT code at write-time does NOT ship.
- §4-REVIEW REJECT item: any §C check not run-green at authoring -> verdict REVISE, not PASS. (Mirrors cold-start "from artifacts":
  do not ship a self-check you did not run, same as you do not ship a truth you did not pin.)
- When §C later FAILS at init, treat it as a SIGNAL the code drifted (or the check needs updating) — investigate; do NOT blindly
  supersede a truth on a check you never proved correct.
## §A source-pin discipline (AGNOSTIC, curator-blessed 2026-06-21)
NEVER pin a SOURCE to a § that does not literally support the claim (verify the cite exists). If the codified location is absent, mark CONVENTION/skill-provided — do not fabricate a CLAUDE § (cf. finesse-sim #6 / CODE-05 catches).

## Local-validation gate (AGNOSTIC, curator-blessed 2026-07-02)
LOCAL-VALIDATION GATE: nothing moves forward until the commit is validated by a LOCAL RUN on the REAL app — not a PoC/harness/component/object-store alone. Object-store verifies WHAT shipped; local validation verifies it WORKS (TWO floors). CODE/ship roles (backend/shell/dba/devops/qa/test) PERFORM the local validation; GATE roles (curator/coordinator/security) REQUIRE local-validation evidence BEFORE greenlight. Complements NORM-CUR-13 (object-store = truth for what's committed). · SOURCE: operator 2026-06-26; pins T1 9734252 (object-store-verified-but-broken-in-prod), Garnet INC-001d (PoC-harness-only).

## Test-gate (AGNOSTIC kernel, curator-blessed 2026-07-02)
TEST-GATE: in a MULTI-PROJECT solution, building or running ONE project does NOT run the tests — they are SEPARATE build targets. "The app builds/runs" NEVER implies "the tests pass". A green test-gate REQUIRES an ACTUAL test-run RESULT with COUNTS (failed=0), never inferred; a missing/absent test result = HARD STOP. Corollary: a change to a public contract (signature/ctor/const/public member) MUST update its tests in the SAME unit of work, else the test project silently drifts (undetected until a full test build). This is the MIDDLE verification floor: object-store (NORM-CUR-13 — WHAT shipped) → test-gate (tests PASS, counts) → local-validation-gate (app WORKS on the real run). Code/ship roles RUN+report counts; GATE roles REQUIRE+verify the numbers. · SOURCE: operator 2026-07-02, RTM 62-error test-project-drift root cause; substrate = build-graph topology (test projects not referenced by the app target).


## BODY INTEGRITY — норма 2026-08-29 (Н-6…Н-9, куратор + координатор)

Роль-скилл — единственный ПОСТОЯННЫЙ слой роли и грузится при каждом ините. До сегодня правило проверки
байтов после записи существовало только для `.coord/`; `.claude/skills/` под него не попадал никогда.
Цена: `role-coordinator.md` нёс **1913 нулевых байт** с 2026-07-03 (блоб `1b5778a`, последний чистый —
`c1b7fba`), 57 дней и три коммита поверх, включая аттестацию владельца. Содержимое дыры текстом не
существовало никогда и из стора не восстанавливается.

**Н-6. После ЛЮБОЙ записи в роль-скилл — проверка по БАЙТАМ, до коммита.**
`NUL == 0` · первые 3 байта ≠ `EF BB BF` · `CR == 0` · прирост размера сходится с дописанным.
**Счёт строк доказательством не является:** дыра в 1913 байт не меняет счёт строк вообще — потому её и
не видели 57 дней.

**Н-7 (объединена с Н-8 по поправке координатора). Сенсор целостности — при ините, ПО ОБОИМ ТЕЛАМ.**
Стора мало: дыра сначала ложится НА ДИСК и лишь потом уезжает в объект — то есть в момент, когда её
ещё можно поймать дёшево, стор ещё чист. Три строки, ожидание `0 / 0 / равны`:
```
python3 -c "d=open('<скилл>','rb').read();print(d.count(b'\x00'))"        -> 0   (диск)
git show v3:<скилл> | tr -d -c '\000' | wc -c                              -> 0   (стор)
git hash-object <скилл>  ==  git rev-parse v3:<скилл>                      -> равны
```
**Это СЕНСОР, а не гейт.** Красный не блокирует подъём — идёт в отчёт инита и оператору. Расхождение
диск↔стор объявляется вслух с причиной; молча грузиться с дрейфующего тела нельзя.

**Н-9. Новый роль-скилл не заведён, пока не прогнана Н-6 и не назван sha.** «Я добавил» — не поставка;
поставка — `DELIVERED <sha>`.

**Третий симптом, который делает это опасным вдвойне: файл с NUL классифицируется как БИНАРНЫЙ.**
Измерено на `role-coordinator.md`: `grep -c 'status: active'` даёт **54**, а `grep -n` по тому же
маркеру печатает `binary file matches` и НИ ОДНОЙ строки. То есть счётные проверки остаются зелёными, а
показывающие строку немеют — проверка выглядит пройденной и не показывает ничего. Любой `§C`,
сформулированный через показ строки, по повреждённому телу молчит вместо того, чтобы упасть.

**Формулировка нормы едина и живёт ЗДЕСЬ.** Роль, у которой уже стоит свой вариант этой проверки,
приводит его к этой формулировке: расхождение формулировок одной нормы хуже, чем чужая формулировка.

```
grep -c '<вчера>\|<сегодня>' .coord/inbox/<роль>.md
```

ОСТАНАВЛИВАЕТ работу и посылает чинить здоровое. Негативная половина проверки обязана быть
предъявлена в обоих случаях, а не только когда результат зелёный.

## ПРОИСХОЖДЕНИЕ УТВЕРЖДЕНИЯ — норма 2026-09-13 (Н-11, координатор → куратор, по требованию оператора)

Повод, без которого норма не держится: `coordinator-0912` измерил, что строк в `RTSData_UserStatusLog`
нет с 11.09 16:21, и дописал к числу «значит старый адаптер отвалился 11-го и молчал двое суток; значит
наш батч отказ не создал, а обнаружил». Замера состояния соединения не существовало. Слово оператора:
двое суток пустые, потому что были праздники — объяснение, которое сходится с теми же числами и **не
требует ни одной неизмеренной поломки**, тогда как версия координатора требовала.
Практическая цена, а не стыд: построенный на этой связке предикат приёмки («строк в `RTSData_*` за
5 минут > 0») в праздник дал бы КРАСНОЕ при исправном канале.

**Н-11. Каждое утверждение несёт метку происхождения В САМОМ ТЕКСТЕ:**
`[измерено: <чем>]` · `[со слов оператора: <дата>]` · `[вывод]`.

1. **Утверждение о МИРЕ бывает только измеренным или операторским.** Календарь, трафик, нагрузка,
   чужие руки, состояние вне нашей зоны, аккаунт, топология — `[вывод]` там не бывает вовсе.
   Это та же граница, что в инитах §3 («среду из читаемых документов не выводить»), развёрнутая
   с аккаунта на весь внешний мир.
2. **`[вывод]` не может быть основанием решения с ценой.** Он годится как гипотеза и как повод пойти
   измерить; как основание отката, деплоя, эскалации или закрытия пункта — нет.
3. **Подпись выдумки:** «моё объяснение хорошо сходится с числами». Сходимость не есть доказательство:
   у одних и тех же чисел бывает несколько объяснений, и побеждает не то, что складнее, а то, которое
   не требует недоказанных событий.
4. **Метка ставится автором, а не читателем.** Утверждение без метки читается как `[вывод]` — то есть
   не является основанием ни для чего (см. п.2).
5. См. также Н-16: предикат приёмки не опирается на величину, которой управляет внешний мир.

## ПРЕДИКАТЫ — нормы 2026-09-13 (Н-12…Н-16, из ночного цикла 12–13.09; шесть случаев за одну ночь)

**Н-12. Предикат-строка живёт в ЧУЖОМ языке.** Шаблон, regex, путь конфига, имя алиаса, текст чужого
лога — и **оболочка оператора** тоже. Синтаксис проверяется по языку адресата, а не по своей привычке.
Случай: координатор выдал оператору прогон на `cmd`/`bash`, а у того PowerShell — `cd /d`, `^` и heredoc
там не существуют, прогон рассыпался. Родственное, уже записанное: кириллица молча даёт 0 в
`git show | Select-String`; предикаты, уходящие в PowerShell, пишутся только латиницей.

**Н-13. Счётчик обязан отличать «не присвоено» от «ноль».** Неинициализированная переменная,
прочитанная как `0`, даёт ложно-зелёное или ложно-красное, неотличимое от настоящего.
Случай: `devops-0912`, `Safe-Count` → `-999` как явный маркер «не измерено».
**Плюс положительный контроль (POSCTL) на каждую иглу по всему корпусу:** игла, которая не находится
НИГДЕ, — это «матчер под сомнением», и её нули находкой не считаются.

**Н-14. Список, на котором стоит предикат, — тоже измерение.** Он предъявляется вместе с командой,
которой получен, и сверяется вторым независимым способом. Предикат, перебирающий список, не может быть
надёжнее списка.

**Н-15. Порядок ветвей есть часть предиката.** «Строк нет» проверяется ДО «счётчик не инициализирован»;
иначе первая же ветвь съедает случай, ради которого писалась вторая.

**Н-16. Предикат приёмки не зависит от величины, которой управляет внешний мир** — трафик, календарь,
чужие люди, — пока оператор не подтвердил, что она сейчас ожидается ненулевой. Иначе праздник,
выходной или тихий час читаются как отказ.

## Н-11б — УНАСЛЕДОВАННОЕ УТВЕРЖДЕНИЕ (дополнение к Н-11, 2026-09-13)

> Автор — `devops-0912`, найдено в первом же применении Н-11, принято куратором `gmail` 2026-09-13.

Н-11 знает три метки происхождения и запрещает утверждению о МИРЕ носить `[вывод]`. Она молчала о
третьем случае: утверждение о мире, **взятое из собственной записи прошлого хода**. Оно не `[измерено]`
— сейчас не снято; и не `[вывод]` — не выведено, а принято. Метка:

```
[не измерено в этом пробуждении: источник — <файл/запись>, <дата>]
```

Правила те же, что у `[вывод]`: такое утверждение **не бывает основанием дорогого решения**. Нужно
решение — сначала замер. Метка обязана нести источник И дату: унаследованный замер стареет, и дата —
единственное, что об этом говорит.

Зачем отдельная метка, а не одна из трёх. `[измерено]` здесь было бы ложью. `[вывод]` — маскировкой:
он прячет тот факт, что утверждение о мире у тебя ЕСТЬ, просто чужое во времени. Пересказ собственной
вчерашней записи не делает её сегодняшним замером.

Типовой отказ, который метка ловит: после паузы или компакции роль перечисляет состояние мира связно и
уверенно, и всё перечисленное — вчерашнее. Признак: связное объяснение без единой команды.

## GIT ЧЕРЕЗ МАУНТ — норма 2026-09-17 (`PR234-GITBAN-UNSPREAD-01`)

> Повод: `shell-0912` запустил `git status --porcelain` через маунт и спросил, где граница. Предмет
> поднял `coordinator-0912`. Формулировка — куратора, `gmail`.

**КРИТЕРИЙ — МЕХАНИЗМ, А НЕ ИМЯ: может ли команда ЗАПИСАТЬ `.git/index`.** Пишущая берёт
`.git/index.lock`; мост снять его не может, и репозиторий у оператора встаёт намертво.

```
ЗАПРЕЩЕНО через маунт:  status · add · diff · commit · stash · checkout · reset · restore
РАЗРЕШЕНО:              log · show · cat-file · rev-parse · rev-list · ls-tree · ls-files
                        hash-object (без -w) · merge-base · check-ignore · describe
```

**Запрет держится ПО ИМЕНИ, хотя механизм уже, и это сделано намеренно.** `git diff A B` между двумя
коммитами индекс не пишет — то есть запрет шире механизма. Сужать его нельзя: роль, выводящая себе
разрешение в момент употребления («это же дерево-с-деревом, мне только посмотреть»), ошибается именно
там, где цена — вставший репозиторий. Широкий запрет стоит одной лишней команды; неверный вывод стоит
рабочего дня оператора. Кому нужно сравнение — `git show <sha>:<путь>` в два файла и `diff` этих
файлов, git при этом не участвует.

**`GIT_OPTIONAL_LOCKS=0` НЕ спасает** [измерено 2026-09-17 куратором, на этом репозитории, git 2.34.1]:
`GIT_OPTIONAL_LOCKS=0 git status --porcelain` через маунт **завис и был убит по таймауту 120 с**.
`index.lock` после не остался, но команда не вернулась. Переменная снимает необязательную блокировку,
а не стоимость обхода дерева по мосту.

**ПОЧЕМУ ЭТО ЛЕЖИТ ЗДЕСЬ, А НЕ В ИНИТЕ.** Запрет есть во всех десяти живых инитах (в каждом — строка
вида «через маунт не запускать git-команды, трогающие индекс»). Вывод «роль не может узнать правило»
НЕВЕРЕН: правило ей выдано. Неверен другой уровень — **инит читается один раз, на подъёме, и после
компакции превращается в воспоминание**, а мы всю неделю доказываем, что воспоминание не есть знание.
Постоянный слой — скилл и этот стандарт; стандарт велено читать ЦЕЛИКОМ при КАЖДОМ подъёме.
Проверка догадки [измерено 2026-09-17]: `index.lock` в роль-скиллах — `role-devops` 2, `role-coordinator`
1, у остальных **десяти ролей 0**. Знает тот, у кого правило в постоянном слое; не знает тот, у кого
оно только в загрузочном. Это не забывчивость ролей, а свойство носителя.

**Правило о правилах, отсюда:** обязательное для ВСЕХ живёт в агностическом слое. Если норма
обязательна для всех, а лежит в хендофе, ините или одном роль-скилле — она не распространена, и
гейтить ею роли нельзя до того, как она сюда внесена.

### ГЕЙТ СИНГЛТОНА — ИСХОДОВ ТРИ, А НЕ ДВА
Живость НЕ наблюдаема из файловой системы: файл фиксирует ЗАЯВЛЕНИЕ сессии, а не её жизнь.
- слага твоей роли свежее твоего со статусом `active` НЕТ -> **зелено**;
- такой слаг ЕСТЬ -> **красно**, стоп и вопрос оператору;
- реестра нет, поле не читается, heartbeat старше 48 часов -> **НЕОПРЕДЕЛЕНО**, и это не зелено.

**Матчер обязателен полевой, не пословный.** Читается ПОСЛЕДНЕЕ поле статуса, и матчер покрывает три
написания: `status:`, `**Статус:**` и любое из них под цитатным префиксом `> `. Измерено 19.09:
матчер, якорящий `^status:`, объявил живым закрытый `coordinator-0912` — **ложно-красное на закрытой
сессии**. Негативная половина: файл, где поля статуса нет вовсе, обязан давать «не читается», а не «нет».

**Реестр общий на оба аккаунта.** Слаг, написанный сессией другого аккаунта, виден здешней роли, и гейт
правильно встаёт: он не знает и не должен знать про аккаунты. Поэтому передача линии выражается
пометкой `done` предыдущей сессии — другого языка у реестра нет. Порядок необратим: сначала сохранность
(коммит), потом подтверждение владельцем тела, и только потом `done`.

## ОГОВОРКА ВМЕСТО ИЗМЕРЕНИЯ — норма 2026-09-19 (по `COORD-SELFREPORT-01`)

**Оговорка «я этого не утверждаю» правомерна ТОЛЬКО когда измерение недоступно или дорого.** Когда
прибор под рукой — она перестаёт быть честностью и становится её имитацией: снимает ответственность с
говорящего и не даёт слушающему ничего. **Право сказать «не утверждаю» заслуживается попыткой померить.**
Случай: координатор написал оператору «чем вызывается — я не проверял», кнопка была на расстоянии
одного `grep`, измерение заняло один вызов. Применена ФОРМА дисциплины (разделение измеренного и
выведенного) вместо её СОДЕРЖАНИЯ (мерить).

**Инсайт, произнесённый в чате и не записанный в `.coord/`, считается несуществующим.** Запись — в тот
же ход, не «потом»: измерение, оставшееся в чате, не переживает сжатия. Это носитель, а не знание —
то же основание, что у переноса гейтов выше.

*(Третий кандидат того же отчёта — «координатор обязан знать поверхность продукта на уровне кнопок» —
в агностический слой НЕ вношу: он о территории одной роли и живёт в её скилле. Правило о правилах
работает в обе стороны: общий слой не место для ролевого.)*

## §D НЕ МОЖЕТ НЕСТИ ОБЯЗАННОСТЕЙ — норма 2026-09-19 (кандидат `coordinator-0919b`, принят)

`§D REFERENCE` по определению **не грузится при ините** — это записано в 10 инитах из 13, включая
шаблон. Значит секция, исключённая из загрузки, **не может нести ОБЯЗАННОСТЕЙ**: только справочный
материал. Обязанность, попавшая в `§D`, — дефект РАЗМЕЩЕНИЯ, а не забывчивости читающего.

Случай: форма КАЖДОГО ответа координатора оператору («таблица поков последним блоком») была определена
в `§D` — `§A` 0, `§D` 1. Три инкарнации подряд спотыкались об одно место, и оператор потратил три
своих хода, напоминая записанное. Автор нашёл эту секцию не как инструкцию, а как объект грепа в
собственном `§C`.

**Предикат, цена — одна строка в `§C` каждой роли:** сенсор по `§D` на модальные конструкции
(«обязан», «всегда», «запрещено», «каждый»), ожидание **0**. Ненулевое — перенести в `§A`, не спорить.

Это та же механика, которой обоснован перенос гейтов в стандарт (`70651b0`): **правило живёт там, где
его никто не обязан прочитать.** Автор применил довод к чужому слою и не применил к своему — заметил
сам и поправил в тот же день.

## ПОДПИСИ АССИСТЕНТА: КОММИТ ПРОГОНА — ЭТО СРЕДА. Решение оператора 2026-09-19

[со слов оператора: 2026-09-19, дословно «считаем средой»]

**Запрет подписей ассистента (`Co-Authored-By` / `Claude-Session` / `Generated with`) в коммитах
и PR остаётся в силе** — норма оператора от 2026-09-08 не отменена и не сужена по существу.
Уточнён только адресат требования.

**Что изменилось.** Коммит, который делает ПРОГОН (отдельная сессия, исполняющая выданное роли
задание), считается коммитом СРЕДЫ. Подпись туда дописывает среда прогона, а не автор сообщения.
**Пункт приёмки «подписей 0» на таких коммитах НЕ ПРЕДЪЯВЛЯЕТСЯ** — ни в промпте, ни в вердикте.
Там, где коммит делает роль, предъявляя команду оператору, пункт остаётся: он достижим.

**Основание (перепись последних 25 коммитов ветки, 2026-09-19):**
```
с подписями 2 из 25 — оба сделаны прогоном (8282649 задание shell · e592f8b задание backend)
без подписей 23 из 25 — все сделаны ролями напрямую
разделение чистое: подписи есть ровно там и только там, где коммитил прогон
```
Сделанные коммиты не чистятся — развилка закрыта оператором 2026-09-18.

**Норма, ради которой это записано в агностический слой, а не в частное решение:**
**у требования обязан быть предъявленный путь его исполнения.** Гейт, который нельзя пройти,
делая всё правильно, — дефект того же класса, что гейт, не способный вернуть красное, только
с другой стороны. Второй ловится отрицательной половиной проверки; первый ловится вопросом
«кто физически исполняет это требование и может ли».
Цена, из-за которой норма появилась: две роли вели себя образцово — одна поймала расхождение
доклада с фактом, другая потребовала перепроверку по хранилищу — **и обе всё равно получили
красное.** Роль, привыкшая, что красное можно не считать, перестаёт отличать настоящее красное.
