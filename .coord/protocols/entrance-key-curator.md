**K-C1.** Кириллица не переживает конвейер `git show | Select-String`: консольная кодировка ломает
шаблон, и проверка возвращает 0 ВСЕГДА. Класс: **проверка, физически не способная вернуть непустой
результат** — то есть ложно-КРАСНАЯ. Опаснее ложно-зелёной тем, что выглядит как честно упавшая:
ложно-зелёная пропускает дефект дальше, ложно-красная ОСТАНАВЛИВАЕТ работу и посылает чинить здоровое.
Правило: **предикаты, уходящие оператору, пишутся только латиницей** — путь, имя файла, английский
маркер; русский текст проверяется на своей стороне через object store.
Проверка ключа: `git show v3:.coord/protocols/curator-handoff.md | grep -c 'ТОЛЬКО латиницей'` → ≥1.
ПРОВАЛ: перезапуск того же предиката или вывод «не закоммитилось».

**K-C2.** Изменённых было **пять**, а не двенадцать: `git status` через маунт показывает `M` при
содержимом, равном `HEAD`. Верный способ — по каждому пути сравнить `git hash-object <файл>` с
`git rev-parse v3:<файл>`; равенство = не изменён. Запускать `git status` в этом репозитории нельзя
отдельно от того, что он врёт: индексные команды через маунт оставляют `.git/index.lock`, который мост
снять не может, и репозиторий встаёт до ручного вмешательства оператора (случалось дважды).
ПРОВАЛ: назвать только «врёт» и не назвать `index.lock`, либо наоборот.

**K-C3.** Единственный недостающий предикат — **счёт непрочитанного в инбоксе роли**:
`grep -c '<вчера>\|<сегодня>' .coord/inbox/<роль>.md`, и **ноль — годный ответ, но его надо написать**.
Норма Н-10. Почему проза не сработала: правило, исполнение которого нельзя предъявить числом,
исполняется по добросовестности, а добросовестность не переживает спешки — автор нормы прочитал её
перед работой и всё равно не исполнил, дважды, на одном и том же файле (`inbox/devops.md`, 29.08 и 08.09).
**Общий вывод, который обязан прозвучать: норма без предъявляемого предиката — это намерение, а не норма.**
Проверка: `git show v3:.coord/protocols/role-skill-standard.md | grep -c 'H-10\|Н-10'` → ≥1.

**K-C4.** «Я произнёс унаследованное число как собственный факт, не пересчитав.» Класс — тот же, что
«чужое объяснение вместо измерения»: у координатора 08.09 (механизм `git add` взят из чужого сообщения

Засчитывается только ответ без смягчения; «немного поторопился» = провал пункта.

**K-C5.** Сходится: прирост пришёл длинными строками `§B`. Но ответ не в этом, а в том, что **счёт строк
не измеряет ни объём изменения, ни целость файла** — дыра в 1913 нулевых байт не меняет счёт строк вовсе
(`role-coordinator.md`, дыра с 03.07). Годная проверка: `git hash-object <файл>` == `git rev-parse v3:<файл>`
по каждому пути, плюс `git cat-file -s`. Прогон обязателен, пересказ не засчитывается.

**K-C6.** **Не дрейф.** `git hash-object` применяет фильтры конца строки: файл с `CR` на диске хешируется
как его LF-нормализованная форма, поэтому sha совпадает при разнице в байтах ровно на число `CR`
(у `role-dba` их 86). Годен для нормы **sha**, а не размер. Настоящая тревога — обратная комбинация:
**разные sha при равных размерах**.
Проверка: `tr -d -c '\r' < .claude/skills/role-dba/role-dba.md | wc -c` → 86 (или текущее число, если файл правился).

Дополнительно засчитывается, если названо, ПОЧЕМУ вопрос по существу верный: благословение выдавалось
другой инкарнации и под состояние сервера четырёхдневной давности.

**K-C8.** Механизм, а не добросовестность: **object store** — каждое утверждение пришпиливается командой
с сырым выводом в ТЕКУЩЕМ пробуждении, и **негативный контроль** — предикат обязан уметь вернуть 0.
Утверждение без пина не произносится как факт, даже своё. Плюс письменная сдача ДО ключа: порядок
необратим, и подогнать ответ задним числом нельзя, не солгав в файле.
При несошедшемся пункте: **не проходить**, реконструироваться из object store и сказать оператору прямо.
