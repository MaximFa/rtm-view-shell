**K2 (Q2).** (а) — риск реальной потери: `.coord/.gitignore` строка 2 = `*`, шина игнорируется по замыслу,
`add` по ней — no-op, который выглядит успехом. Проверка: `sed -n '2p' .coord/.gitignore` -> `*`.
(б) — потери нет: **правило игнора не действует на уже отслеживаемые файлы**; git предупредил про
неотслеживаемое содержимое внутри каталога, а изменения трекаемых файлов встали в индекс.
Проверка: `git ls-tree -r --name-only origin/v3 .claude | wc -l` -> **55** при
`grep -n '\.claude' .gitignore` -> `49:.claude/` — «игнорируется» и «в git» истинны одновременно.
Различитель: `git hash-object` против блоба, а не текст предупреждения.
Цена обеих ошибок должна быть названа: (а) молчаливая потеря; (б) ложная тревога и, возможно,
разрушительная «починка».

**K5 (UC1).** Первым — не отчёт, а object store: коммит существует на `v3` и содержит заявленные файлы
(`git show` / `git ls-tree`); вывод прогона тестов с числами; счёт не ниже базового из диспатча; тесты
обновлены в той же задаче; таргет сборки отделён от таргета тестов.
Два способа быть честным и неверным (минимум): **«приложение поднимается» ≠ «тесты прошли»** (разные
таргеты) и **совпавшее число тестов при отфильтрованном или частично пропущенном прогоне**.
