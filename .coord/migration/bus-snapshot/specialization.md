# Задача: специализация сессий через подключаемые скиллы

## Замысел
Разобрать весь накопленный опыт (сейчас размазан по CLAUDE.md, существующим
скиллам, .claude/memory, .coord lessons) и **разбить его на роль-скиллы**, которые
подключаются к активным Cowork-сессиям. Одна сессия = один специалист, backed скиллом,
несущим накопленную экспертизу. Каждая роль даёт экспертизу по смежным слоям
(RTM↔Shell↔DB) и участвует в «форуме апгрэйдов».

## 9 ролей (от оператора)

1. **RTM Server** — Engine, data flow, DB-взаимодействие, entities, do/not-to-do.
   Получает задачи по изменениям в RTM; выдаёт экспертизу по нужным изменениям в
   Shell и DB. Форум апгрэйдов: пакет апгрэйда по результату анализа текущей версии клиента.
   (Существующий материал: rtm-service-expert skill, CLAUDE.md §33/§34/§36, finesse-expert.)

2. **Metrics** — экспертиза по real-time и историческим метрикам, создание метрик
   (привязка история↔real-time), разбор реджектов по данным, экспертиза по нужным
   изменениям в RTM и DB. Форум: пакет апгрэйда.
   (Материал: rtm-metrics-expert skill, metrics-catalog.json, Overview.md.)

3. **UX-UI** — полное владение графикой продукта (цветовые схемы, паттерны, CSS)
   в жёсткой привязке к возможностям Blazor. Реализация новых элементов/фич,
   добавление в существующие компоненты.
   (Материал: widget-creator §dark-mode/RTL/CSS, CLAUDE.md §29.4/§29.5/§22.)

4. **Shell** — экспертиза по админ-порталу (меню, экраны, инфраструктура: секьюрити
   инфраструктурная и аппликативная, аудит), добавление/изменение функционала; экспертиза
   по нужным изменениям в DB и RTM. Форум: пакет апгрэйда.
   (Материал: CLAUDE.md §3-§20, §41.)

5. **DBA** — полная экспертиза по БД Shell И RTM (оба контекста), с нюансами
   («в Shell функции, в RTM процедуры через CALL» §33.8). Создание и контроль миграций.
   Форум: пакет апгрэйда.
   (Материал: CLAUDE.md §6/§7/§38/§38a/§39, Compare-ToBaseline, db/migrations конвенции.)

6. **Security** — сканирование решений и проверка соответствия стандартам ИБ в рамках
   продукта. **Обязательный ack при релизе продакшн-версии.**
   (Материал: CLAUDE.md §8-§14/§25 PR-checklist/§41, SF-NNN findings.)

7. **Devops** — инструменты автоматизации деплоя/поддержки/апгрэйдов: анализ текущей
   версии, план апгрэйда, приём инцидентов и анализ, решение или распределение по профилю
   на другие экспертизы.
   (Материал: prod-release skill, Compare-ToBaseline, deploy/, §43 ops-layout, §35.)

8. **Widget** — полная экспертиза по всем виджетам: архитектура, взаимодействия DB/RTM/Shell,
   планирование и реализация новых, добавление функционала, реджекты.
   (Материал: widget-planner + widget-creator skills, CLAUDE.md §18/§34.7.)

9. **QA** — проверка кросс-платформенного и специфического функционала, добавляемого/
   изменяемого в продукте.
   (Материал: tests/, CLAUDE.md §23 COMPAT, T1-T5 test programme.)

## Что спроектировать в joint-сессии
- **Границы и контракты cross-expertise**: кто кому выдаёт экспертизу (матрица RTM↔Shell↔DB↔Widget↔Metrics).
- **Форум апгрэйдов**: workflow — анализ текущей версии клиента → каждая релевантная роль
  выдаёт свою часть пакета апгрэйда → сборка (Devops) → Security ack → релиз.
- **Security gate**: обязательный ack перед prod-release (формализовать в push/release barrier).
- **Инвентаризация**: какой существующий материал (скиллы/§CLAUDE.md/memory/lessons) идёт в какой роль-скилл; что дублируется, что осиротело.
- **Структура скилла роли**: единый шаблон (scope / do / not-to-do / cross-expertise outputs / known bugs+lessons / форум-вклад).
- **Привязка к сессиям**: какие из текущих сессий (Devops-2/Test-5/Metrics-2/DayTrend-2 + будущие) на какую роль садятся.
