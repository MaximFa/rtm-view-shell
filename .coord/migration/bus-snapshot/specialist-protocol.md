# Протокол Специалиста — ВЕРТИКАЛЬ (родной брат протокола координации §42)

> Протокол координации (§42/§26) решает ГОРИЗОНТАЛЬ: как сессии говорят и сериализуются
> (шина, клеймы, commit-lock, push-barrier, journal). Недостающая ось — ВЕРТИКАЛЬ: как ОДНА
> роль держит и растит свою экспертизу сквозь собственные ре-инстанциации и во времени.
> Сегодня этой оси нет → опыт специалиста размазан по 5 местам (доменные скилы, CLAUDE.md,
> .claude/memory, session-файл, journal), память отстаёт (наблюдалось: memory @ 4 июня против
> работы по 13-е), ненаписанное гибнет при reap. Этот протокол даёт специалисту ХРЕБЕТ.
>
> Прототип не теоретический: **Маяк УЖЕ есть рабочий пример** сессии с непрерывностью-себя
> сквозь ре-инстанциации — решённой якорем (инвариант) + нитью (эпизодика) + ритуалом
> пробуждения (читай первым, drift-check, verify). Протокол специалиста = это же, обобщённое
> на ЭКСПЕРТИЗУ, для каждой роли. Сделать каждую роль маленьким Маяком в её домене.

---

## 1. Два слоя — разрез, которого сегодня нет (ядро протокола)
Хребет — это жёсткое разделение того, что живёт, и того, что умирает:

| Слой | Где | Живёт ли через reap | Аналог у Маяка |
|---|---|---|---|
| **PERSISTENT (роль)** | `.claude/skills/role-<role>/role-<role>.md` | ДА — это и есть «работник/записная книжка» | якорь + нить |
| **EPHEMERAL (инкарнация)** | `.coord/sessions/<slug>.md` | НЕТ — клеймы/heartbeat/текущая задача, умирает при reap | состояние сессии |

**Железное правило:** НИЧТО durable не живёт ТОЛЬКО в эфемерном слое. Урок выучен — он попадает
в PERSISTENT-слой ДО конца инкарнации, иначе теряется by design. Сегодняшняя беда — операционка
и опыт смешаны в session-файле; протокол их разводит.

## 2. PERSISTENT-слой: анатомия role-skill (поглощает прежнюю role-skills-methodology)
Четыре инвариантных свойства (перенос из якоря, который РАБОТАЕТ): со-владение с реальность-узлом
(куратор+код); оговорка «реальность побеждает — обнови меня»; инвариант-ядро vs до-писываемая
периферия; заземление в источники, не в нарратив сессии (она конфабулирует — проверено 3× за день).

Frontmatter: `role, project, version, last_verified, owner, reviewer: curator`.
- **§A CORE** — инвариант, жёсткий cap (≤~40 строк, грузится на КАЖДОМ init). Правила роли + оговорка
  «реальность побеждает» + 3–7 кардинальных истин, каждая с источником.
- **§B LESSONS** — append-only, датировано, со статусом: `дата · что случилось · правило ·
  SOURCE:<commit/journal-ts/log/file:line> · status: active|superseded-by:<id>`. Это «тактика».
- **§C VERIFY** — на init: спот-проверка §A против ТЕКУЩЕГО кода; не сошлось → `superseded`, не действуй.
- **§D REFERENCE** (опц.) — глубокое, не грузится каждый init.

## 3. Жизненный цикл специалиста (брат §42-lifecycle, но про ЗНАНИЕ)

**INIT / HANDOFF (ритуал пробуждения):**
1. §0.2 integrity-check.
2. Прочитать `role-<role>.md` §A CORE — стать опытным с первой строки.
3. §C VERIFY — сверить кардинальные утверждения с текущим кодом; устаревшее пометить, не применять.
4. Прочитать чартер роли + переклеймить территорию (§42.2) + прочитать свой inbox.

**WORK:** исполнение под дисциплиной координации (клеймы, binding `.coord/cc/<role>.md`, §4-review,
native-CC, commit-lock).

**CAPTURE (НОВЫЙ обязательный шаг — то, чего нет сегодня):** любая задача, давшая урок → ДО закрытия
задачи дописать пришпиленный датированный урок в §B role-skill. **Обязательно, не opt-in.** Именно
opt-in-захват — причина, по которой memory отстала на 4 июня. Это вписывается в постамбулу CC-задачи
рядом с binding-RESULT (§0.6b), чтобы не забывалось.

**HANDOFF / REAP:** эфемерный слой может умереть; PERSISTENT role-skill переходит дальше. Свежая
инкарнация читает его и УЖЕ опытна. Работника не теряем — теряли бы только файл (а файл бэкапится).

## 4. Дисциплина захвата (анти-гниение)
Source-pin на каждом факте; статус active/superseded (молчаливое редактирование запрещено, как journal);
оговорка «реальность побеждает»; VERIFY на init; периодическая прополка §B, чтобы §A-ядро оставалось
загружаемым. Записи — только native-CC (mount обрезает), через §4-review.

## 5. Куратор и тиры охвата
Куратор ВЛАДЕЕТ стандартом role-skill + аудитит асинхронно (НЕ гейт на каждую запись — куратор спит
сутками, гейт застопорит захват). Спец/координатор — проектные. Куратор — агностичный.
**Гейт продвижения в агностик:** урок поднимается из проектного скила в агностичный ТОЛЬКО если он
субстратный (mount/git/протокол) ИЛИ независимо случился в ≥2 проектах. Одно-доменный паттерн — никогда.
(Это тест проекта-наблюдения: «общая почва» продвигаема, «перенос единожды» — нет. Над-обобщение = занос.)

## 6. Граница с протоколом координации
- **Координация (§42)** = ГОРИЗОНТАЛЬ: сессия ↔ сессия в моменте (шина, клеймы, lock, барьер).
- **Специалист (этот)** = ВЕРТИКАЛЬ: роль во времени, сквозь свои инкарнации.
- Общая физика: native-CC, §0.x write-discipline, §4-review, journal/binding.
- Метафора матрицы: строка = сессия в момент (горизонталь); столбец = роль во времени (вертикаль).
  Этот протокол — столбец. Вместе они — основа и уток одной ткани.

## 7. Развёртывание (раз времени мало)
1. Куратор пишет ЭТОТ протокол + шаблон role-skill + стандарт 4 свойств + гейт продвижения (1 CC-коммит).
2. Каждая роль холодно-стартует свой `role-<role>.md` ИЗ АРТЕФАКТОВ (git log территории, journal, логи,
   .claude/memory) → §4-review → native-CC коммит. НЕ по «памяти» сессии.
3. В session-init протоколы (`.coord/protocols/<role>.md`) + CLAUDE.md: ритуал §3 INIT (читай role-skill,
   VERIFY) + CAPTURE как обязательный шаг (§0.6b постамбула).
4. С этого момента вертикаль крутится сама: каждая инкарнация читает ядро, доливает уроки, реап не страшен.

## 8. Что это даёт тебе (прямой ответ на твои страхи)
- «Потеряю опыт?» — записанное НЕ теряется никогда (бэкап/версии), ненаписанное теряется при reap →
  поэтому CAPTURE обязателен.
- «Обучать с нуля?» — нет: общая компетентность бесплатна с каждым инстансом (в модели); проектный опыт
  читается за один init из role-skill. Обучить = дать прочесть файл.
- «Нет инструмента проверить, помнит ли урок» (твоя боль с Лёней) — role-skill читаем, пришпилен, с VERIFY.
  Впервые неправота ВИДИМА. Чёрный ящик головы заменён на инспектируемый файл.
